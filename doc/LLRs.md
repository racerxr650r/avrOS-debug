# Low-Level Requirements

**Version:** 0.1
**Date:** 2026-05-16
**Author(s):** John Anderson

## 1. Introduction

Each LLR ID follows the pattern `LLR-XXX-NN`, where `XXX` is a module code and `NN` is a zero-padded two-digit sequence number. Module codes: `MAIN` (`src/main.c`), `UPDI` (`src/updi.c`), `RSP` (`src/gdb_rsp.c`), `ELF` (`src/elf_parser.c`), `FSM` (`src/fsm_mapper.c`), `MON` (`src/monitor.c`), `INST` (`Makefile`, `doc/avrOSdb.1`, `doc/UserManual.md`), `HWTEST` (`tests/hw/hw_test.c`). IDs are permanent contracts and may not be renumbered or reused once allocated.

## 2. src/main.c — Entry Point and Event Loop

Requirements for `main()`, `parse_args()`, and `event_loop()`. These functions own the application lifecycle from argument parsing through resource cleanup.

*   <a id="LLR-MAIN-01"></a>**LLR-MAIN-01** — `parse_args()` shall populate an `AppConfig` struct from `argc`/`argv`. If any unrecognised argument is encountered, it shall print a usage message to `stderr` and call `exit(1)`.
    *Trace:* HLR-001 (CLI Argument Parsing).

*   <a id="LLR-MAIN-02"></a>**LLR-MAIN-02** — When not supplied on the command line, `parse_args()` shall apply the following defaults to the `AppConfig` fields: `gdb_port` = 1234, `baud_rate` = 115200, `load_flash` = false. The `<serial-device>` and `<elf-file>` positional arguments are mandatory; absence of either shall trigger the usage error path.
    *Trace:* HLR-001 (CLI Argument Parsing).

*   <a id="LLR-MAIN-03"></a>**LLR-MAIN-03** — `main()` shall call `updi_open()` and validate the returned file descriptor before calling `rsp_listen()`. A failure from either shall cause `main()` to release any already-open resources and return exit code 1.
    *Trace:* HLR-002 (Serial Device Initialisation), HLR-003 (GDB Listener Startup).

*   <a id="LLR-MAIN-04"></a>**LLR-MAIN-04** — When the `--load` flag is set, `main()` shall iterate over all `PT_LOAD` ELF program headers and call `updi_nvm_write_flash()` for each segment whose `p_filesz > 0` and whose virtual address lies below the SRAM base (i.e. flash-resident segments only). Segments with `p_vaddr >= ctx.sram_base` shall be skipped. All qualifying segments shall be written before entering `event_loop()`. A flash write failure shall cause `main()` to print an error to `stderr` and return exit code 1.
    *Trace:* HLR-004 (ELF Flash Load Option).

*   <a id="LLR-MAIN-05"></a>**LLR-MAIN-05** — `event_loop()` shall multiplex `listen_fd`, `gdb_fd`, and `updi_fd` using a single POSIX `select()` call with no timeout. On each iteration it shall: accept a GDB client on `listen_fd` if `gdb_fd` is -1; forward console bytes from `updi_fd` to `stdout` via `updi_console_poll()`; dispatch RSP packets from `gdb_fd` via `rsp_recv_packet()` and `rsp_dispatch()`. No POSIX threads shall be created.
    *Trace:* HLR-003 (GDB Listener Startup), HLR-039 (Single-Threaded Event Loop Architecture).

*   <a id="LLR-MAIN-06"></a>**LLR-MAIN-06** — `main()` shall register a `SIGINT`/`SIGTERM` handler that sets the global `volatile sig_atomic_t g_quit` flag to 1. `event_loop()` shall test `g_quit` at the top of each loop iteration and return immediately when the flag is set, without closing any file descriptors itself.
    *Trace:* HLR-035 (Graceful Shutdown and Resource Release), HLR-039 (Single-Threaded Event Loop Architecture).

*   <a id="LLR-MAIN-07"></a>**LLR-MAIN-07** — On all exit paths, `main()` shall release resources in this exact order: (1) `rsp_close(cfg.gdb_fd)` if `gdb_fd >= 0`, (2) `rsp_close(cfg.listen_fd)`, (3) `elf_close(&ctx)`, (4) `updi_close(cfg.updi_fd)`. The process shall exit with code 0 on normal termination and code 1 on any fatal initialisation or flash-write failure.
    *Trace:* HLR-035 (Graceful Shutdown and Resource Release).

*   <a id="LLR-MAIN-08"></a>**LLR-MAIN-08** — `parse_args()` shall recognise the `--device` long option, set `cfg->device_info = true`, and accept the absence of the `<elf-file>` operand without error. Specifying both `--device` and `--load` on the same command line shall cause `parse_args()` to print `"error: --device is mutually exclusive with --load"` to `stderr`, print the usage synopsis, and call `exit(1)`.
    *Trace:* HLR-044 (Device-Signature Diagnostic Mode).

*   <a id="LLR-MAIN-09"></a>**LLR-MAIN-09** — When `cfg.device_info` is true, `main()` shall: (1) call `updi_open()`; (2) on success call `updi_read_device_info()`; (3) on success format and print to `stdout` a multi-line report containing `Serial device:`, `Baud rate:`, `Signature:` (3 hex bytes), `Family:` (looked up via a static `device_family[]` table indexed by signature \u2014 unknown signatures shall print `unknown device`), `Revision:`, `Serial:` (10 hex bytes), and `UPDI status: SYS_STATUS=0x.. KEY_STATUS=0x.. STATUSB=0x..`; (4) call `updi_close()` and return. The function shall **not** call `rsp_listen()`, `elf_find_avros_tables()`, `fsm_build_thread_list()`, or `event_loop()`. On any UPDI failure the function shall print a verbose diagnostic to `stderr` that names the failed step (e.g. `"updi-open"`, `"sigrow"`, `"sys-status"`) and return exit code 1.
    *Trace:* HLR-044 (Device-Signature Diagnostic Mode).

*   <a id="LLR-MAIN-10"></a>**LLR-MAIN-10** — Before entering `event_loop()`, `main()` shall call `updi_enter_debug(cfg.updi_fd)`, after `updi_open()` and any optional `updi_nvm_write_flash()` (`--load`) steps and before `rsp_listen()`. A non-zero return shall be treated as a fatal initialisation failure and shall trigger the LLR-MAIN-07 teardown with exit code 1. This arms AVR-Dx OCD mode for the lifetime of the server so that all RSP `g`/`G`/`P`/`s`/`c`/`Z0`/`Z1` operations have a halted, OCD-addressable CPU register file available on first use.
    *Trace:* HLR-010 (Execution Control).

*   <a id="LLR-MAIN-11"></a>**LLR-MAIN-11** — When `cfg.load_flash` is true, `load_segments()` shall walk every `PT_LOAD` segment of the open ELF context and classify it by its UPDI virtual address (after folding ELF VMAs below `UPDI_FLASH_BASE` into the FLASH window via `vaddr | 0x800000`). SRAM-resident segments shall be skipped silently. The classifier shall obtain its EEPROM, USERROW, FUSES, LOCK, and SIGROW window bases and sizes from the runtime-selected device descriptor (`updi_get_device()`, see LLR-UPDI-27); no per-family address shall be hard-coded in the classifier. SIGROW segments shall be skipped with a `"SIGROW segment @0x%06x ignored (read-only)"` notice on `stdout`. FLASH segments (everything below the selected device's USERROW base in the UPDI space) shall be padded with `0xFF` to a 512-byte page boundary and dispatched to `updi_nvm_write_flash()` — the established Phase 2/3 path is unchanged. EEPROM, USERROW, and FUSES segments shall be dispatched verbatim (no padding) to `updi_nvm_write_eeprom()`, `updi_nvm_write_userrow()`, and `updi_nvm_write_fuses()` respectively. LOCK segments (`[dev->lock_base, dev->lock_base + dev->lock_size)`) shall additionally require `cfg.erase_chip` to be true (else the function shall return -1 with a diagnostic naming the missing `--erase` flag) and shall be dispatched to `updi_nvm_write_lockbits(..., cfg.allow_lock_updi)`. Any segment whose UPDI address is in none of these windows shall cause `load_segments()` to return -1 with `"error: segment vaddr 0x%06x not in any programmable NVM window"` on `stderr`. The `--allow-lock-updi` CLI flag shall set `cfg.allow_lock_updi` and is forwarded to `updi_nvm_write_lockbits()` unchanged.
    *Trace:* HLR-004 (ELF Load Option), HLR-046 (Non-FLASH NVM Programming), HLR-047 (Lockbit Programming Safety Interlock), HLR-048 (Multi-Family Runtime Device Dispatch).

*   <a id="LLR-MAIN-12"></a>**LLR-MAIN-12** — `parse_args()` shall recognise the option `--force-device=<family>` (case-insensitive value) and store the value in `cfg.force_device` (default `NULL`). The `--help` / `usage()` output shall list the option along with the five supported family names (`AVR-DA`, `AVR-DB`, `AVR-DD`, `AVR-DU`, `AVR-SD`). In normal startup (`app_main()`), after `updi_open()` succeeds, the application shall call `updi_select_device(cfg.updi_fd, cfg.force_device)` and shall treat a non-zero return as a fatal initialisation failure, exiting via the LLR-MAIN-07 teardown with exit code 1. In diagnostic mode (`run_device_mode()`, `--device`), `updi_select_device()` shall be called only when `cfg.force_device` is non-NULL and non-empty, so that unknown silicon can still be probed and its raw SIGROW bytes reported.
    *Trace:* HLR-048 (Multi-Family Runtime Device Dispatch).

*   <a id="LLR-MAIN-13"></a>**LLR-MAIN-13** — `app_main()` shall select the per-family device map between `elf_open()` and the first NVM access by calling `updi_select_device(cfg.updi_fd, cfg.force_device)` exactly once, where `cfg.force_device` is either the user-supplied `--force-device=<family>` string or `NULL`. When `cfg.force_device` is `NULL`, `updi_select_device()` shall determine the active family by SIGROW autodetect (LLR-UPDI-27). The ELF `.note.gnu.avr.deviceinfo` part-name shall NOT be used as a selection input; using it would defeat the mismatch check below by comparing the ELF family against the family the application just told the UPDI layer to be. After `updi_select_device()` returns 0, when `elf_ctx.device_name` is a recognised Microchip part-name (`updi_family_from_partname()` returns non-NULL) AND the user did NOT supply `--force-device`, the application shall verify that `updi_get_device()->family` matches the ELF-derived family string; on mismatch the application shall print `"error: ELF was built for <partname> (family <X>) but target reports <Y> (use --force-device=<Y> to override)"` to `stderr`, exit via the LLR-MAIN-07 teardown with code 1, and shall not call `updi_enter_debug()`, `load_segments()`, or `rsp_listen()`. The `--force-device=<family>` option is the documented escape hatch when the user knowingly wants to debug an ELF against a different silicon family (e.g. a generic AVR-DA build run on AVR-DB hardware) or when SIGROW autodetect cannot identify the part (AVR-DU/AVR-SD relocate SIGROW to a different base).
    *Trace:* HLR-046 (Non-FLASH NVM Programming), HLR-048 (Multi-Family Runtime Device Dispatch).

*   <a id="LLR-MAIN-14"></a>**LLR-MAIN-14** — `parse_args()` shall recognise three new long-form flags and store them as bool fields on `AppConfig`: `--prog` sets `cfg.prog_mode = true`, `--no-verify` sets `cfg.no_verify = true`, and `--no-autobaud` sets `cfg.no_autobaud = true`. The usage banner shall document all three. The flag combination shall be validated: `--prog` is mutually exclusive with both `--device` and `--load` (specifying any pair shall print a usage error to `stderr` and call `exit(1)`); `--no-verify` is a no-op when `--device` is also given (no NVM writes happen in device mode); `--no-autobaud` is meaningful only in `--device` mode. Defaults are `false` for all three flags, preserving pre-Phase-9 behaviour for callers that supply none of them.
    *Trace:* HLR-049 (Read-Back Verify After Load), HLR-050 (Program-and-Exit Mode), HLR-052 (Auto-Baud Link-Quality Probe in Device Mode).

*   <a id="LLR-MAIN-15"></a>**LLR-MAIN-15** — `verify_segments(cfg, elf_ctx)` shall mirror the segment classification logic of `load_segments()` (FLASH / EEPROM / USERROW / FUSES / LOCK / SIGROW) but shall use `updi_nvm_read()` to read each programmed range back from the target in `CHUNK = 256`-byte windows and compare it against the ELF payload. Segments classified as SIGROW (read-only) and LOCK (read-once / lockbits become read-only post-write) shall be skipped. On a window mismatch the function shall compute `updi_crc32()` over the expected and actual buffers and print one `stderr` line per failing page reporting the window name, page-aligned VMA, and both CRC32 values. The function shall call `progress_render()` once per page and `progress_finish()` once per segment to drive the progress indicator. It shall return 0 when every byte of every verifiable segment matches and -1 otherwise. The caller is responsible for translating -1 into the process exit code `UPDI_EXIT_VERIFY_FAIL` (`2`).
    *Trace:* HLR-049 (Read-Back Verify After Load), HLR-050 (Program-and-Exit Mode).

*   <a id="LLR-MAIN-16"></a>**LLR-MAIN-16** — `run_prog_mode(cfg)` shall implement the `--prog` operating mode. It shall: (1) open the ELF binary via `elf_open()`; (2) open the UPDI link via `updi_open(cfg->serial_device, cfg->baud_rate)` and call `updi_select_device(cfg->updi_fd, cfg->force_device)`; (3) print one `baud=<N>` line to `stdout` reporting the negotiated UART rate; (4) when `cfg->erase` is true, call `updi_chip_erase(cfg->updi_fd)`; (5) call `load_segments(cfg, &elf_ctx)` to program FLASH/EEPROM/USERROW/FUSES/LOCK; (6) unless `cfg->no_verify` is set, call `verify_segments(cfg, &elf_ctx)`; (7) on verify success print `verify: OK` to `stdout`; (8) close UPDI and ELF resources and return. The function shall NOT call `updi_enter_debug()` and shall NOT call `rsp_listen()` — the target is left running. Return-value mapping: 0 on success, 1 on any I/O / NVM failure, and `UPDI_EXIT_VERIFY_FAIL` (`2`) when verify reports a mismatch. The main dispatcher shall route to this function immediately after the device-info short-circuit when `cfg->prog_mode` is true.
    *Trace:* HLR-050 (Program-and-Exit Mode), HLR-049 (Read-Back Verify After Load).

*   <a id="LLR-MAIN-17"></a>**LLR-MAIN-17** — The progress indicator shall be implemented by two static helpers `progress_render(phase, window, page, total_pages, percent)` and `progress_finish(void)`. When `isatty(STDOUT_FILENO)` is true `progress_render()` shall emit an in-place ANSI-friendly single-line bar of the form `[####....] PPP%% page N/M PHASE WINDOW` followed by carriage return (no newline) and `progress_finish()` shall emit a final newline to terminate the line. When `stdout` is not a TTY `progress_render()` shall emit one full newline-terminated line per call and `progress_finish()` shall be a no-op. Both helpers are called from `load_segments()`, `verify_segments()`, and `run_prog_mode()`. Additionally, `run_device_mode()` shall, after the existing SIGROW / REVID / ASI status print and unless `cfg->no_autobaud` is true, call `updi_probe_baud(cfg->serial_device, 8, autobaud_report_cb, NULL)` BEFORE opening the UPDI link and pass the selected rate to `updi_open()`; and shall, after the existing report, read the full FUSES window and the 4-byte LOCK window via `updi_nvm_read()` and emit the decode via `updi_format_fuses()` into a 2 KiB stack buffer.
    *Trace:* HLR-050 (Program-and-Exit Mode), HLR-051 (Fuses Pretty-Printer in Device Mode), HLR-052 (Auto-Baud Link-Quality Probe in Device Mode).

*   <a id="LLR-MAIN-21"></a>**LLR-MAIN-21** — `parse_args()` shall recognise `--allow-erase` as a boolean flag (no argument) and set `cfg->allow_erase = true` when present. The default initialiser shall set the flag to `false`. The `usage()` help text shall include a one-paragraph description naming the verbs it unlocks (`monitor erase`, `monitor chip-erase`) so operators see the gating relationship without consulting the man page. The flag value shall be propagated to the constructed `RspContext` at server start by assigning `ctx.allow_erase = cfg->allow_erase ? 1 : 0;`, and the default breakpoint mode shall be set to `RSP_BP_MODE_SW` in the same initialiser block.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MAIN-23"></a>**LLR-MAIN-23** — `parse_args()` shall recognise `--log-rsp` as a boolean flag (no argument) and set `cfg->log_rsp = true` when present. The default initialiser shall set the flag to `false`. The main orchestrator shall pass this flag to `rsp_set_logging()` before entering the event loop.
    *Trace:* HLR-068 (Detailed RSP Traffic Logging).

*   <a id="LLR-MAIN-22"></a>**LLR-MAIN-22** — `main()` and `event_loop()` shall emit lifecycle log lines to `stderr` per HLR-065. Specifically: (a) immediately after `rsp_listen()` returns a non-negative fd in `app_main()`, print `"avrOSdb: listening on :%u\n"` with `cfg.gdb_port`; (b) inside `event_loop()`, after every successful `rsp_accept()` that yields a non-negative fd, call `getpeername()` on the new fd and print `"avrOSdb: client connected from %s:%u\n"` with the dotted-quad IPv4 address and port from the returned `sockaddr_in`; on `getpeername()` failure print `"avrOSdb: client connected from <unknown>\n"`; (c) when `rsp_recv_packet()` returns 0 print `"avrOSdb: client disconnected (EOF)\n"` before closing the fd, when it returns negative print `"avrOSdb: client disconnected (read error: %s)\n"` with `strerror(errno)`; (d) after `rsp_dispatch_n()` returns, if `gdb_fd < 0` (the handler closed the socket) and `rctx.disconnect_reason != NULL`, print `"avrOSdb: client disconnected (%s)\n"` with that reason and clear the field by setting it to `NULL`; if instead `gdb_fd >= 0` but `disconnect_reason != NULL` (vKill while listener-survival is still TODO), print the same line, then close `gdb_fd` and clear it locally; (e) immediately after `event_loop()` returns in `app_main()`, before the `teardown:` label runs, print `"avrOSdb: shutting down (%s)\n"` where the reason is selected from a `volatile sig_atomic_t g_shutdown_signal` set by `sig_handler()` (`SIGINT`/`SIGTERM`) when applicable, defaulting to `"fatal: <best-effort context>"` for any other quit path. The signal handler shall record `signo` into `g_shutdown_signal` in addition to setting `g_quit = 1`. All log lines shall use `fprintf(stderr, ...)` followed by `fflush(stderr)`; no new flag gates them and they shall not be emitted on `stdout`. Duplicate emissions for the same transition are forbidden — only one disconnect line per fd-close.
    *Trace:* HLR-065 (Lifecycle Logging).

## 3. src/updi.c — UPDI Physical Layer

Requirements for all public functions in `src/updi.c`: link initialisation, memory access, execution control, NVM programming, and console bridging.

*   <a id="LLR-UPDI-01"></a>**LLR-UPDI-01** — `updi_open()` shall open the UART device and configure it for 8E2 framing (8 data bits, even parity, 2 stop bits) in raw half-duplex mode using `termios`. `cfmakeraw()`, `CS8`, `CSTOPB`, `PARENB` (with `PARODD` cleared), and explicit baud setting via `cfsetispeed()`/`cfsetospeed()` shall be applied. If `tcsetattr()` returns `EINVAL` when setting `PARENB` (Linux PTY slaves strip parity from virtual terminals), the function shall retry with `PARENB` cleared so the link still works against PTY-backed test harnesses. The function shall return the open file descriptor on success or -1 on failure.
    *Trace:* HLR-006 (UPDI Hardware Connection).

*   <a id="LLR-UPDI-02"></a>**LLR-UPDI-02** — `updi_open()` shall execute up to three cold-start attempts. Attempt 0 (fast path) shall write a single 0x00 wake byte at the configured session baud rate, followed by `tcdrain()` and `tcflush(fd, TCIFLUSH)` to discard the half-duplex echo. Attempts 1 and 2 (slow path) shall instead generate a multi-millisecond line-low pulse by temporarily switching the kernel baud rate to 300 baud with `CSTOPB` cleared (1 stop bit) via `tcsetattr(TCSADRAIN)`, then writing two 0x00 bytes each followed immediately by `tcdrain()` to guarantee the byte is actually clocked out of the UART FIFO before the next operation. Each byte at 300 baud holds the TX line low for ≈33 ms (≥60 ms total — sufficient to reset the target's UPDI clock and contention detector on a cold power-on with passive single-wire combiners), and the half-duplex echoes are read-and-discarded at 300 baud. After both BREAK bytes, `updi_open()` shall sleep ≈50 ms (`nanosleep()`) so that any echo bytes still in flight on the line bus reach the kernel RX queue at 300-baud framing, then `tcflush(TCIFLUSH)` discards them. Only then shall the session baud rate be restored (`tcsetattr(TCSADRAIN)` followed by a second `tcflush(TCIFLUSH)`). Without `tcdrain()` after each write, the subsequent baud switch flushes or re-clocks the queued BREAK byte, destroying the line-low pulse; without the 50 ms settle, late echo bytes arrive AFTER the baud restore, get framed at 115200 baud, and desynchronise every subsequent frame echo. This mirrors avrdude's `serialupdi` programmer exactly (verified by `strace`) and is necessary because no portable POSIX API generates a multi-ms BREAK on demand — `tcsendbreak()` is too short and not honoured by all kernel UART drivers (notably the RPi PL011).
    *Trace:* HLR-006 (UPDI Hardware Connection), HLR-036 (UPDI Cold-Start Contention Handshake).

*   <a id="LLR-UPDI-03"></a>**LLR-UPDI-03** — After the wake byte (attempt 0) or 300-baud double-break (attempts 1–2), `updi_open()` shall transmit `STCS ASI_CTRLB = ASI_CTRLB_CCDETDIS` (0x08) to disable the target's collision/contention detector, then `STCS ASI_CTRLA = ASI_CTRLA_IBDLY` (0x80) to enable inter-byte delay on the target's responses, then probe the link with `LDCS ASI_STATUSA` (opcode `0x80 | 0x00 = 0x80`). `ASI_STATUSA` carries UPDIREV in its upper nibble and is always readable while UPDI is enabled, including before any reset. If any STCS write or the LDCS probe fails, `updi_open()` shall advance to the next attempt. After 3 consecutive failed attempts the function shall return -1 and the caller shall treat the link as unavailable.
    *Trace:* HLR-036 (UPDI Cold-Start Contention Handshake).

*   <a id="LLR-UPDI-04"></a>**LLR-UPDI-04** — `updi_mem_read()` and `updi_mem_write()` shall transfer up to `UPDI_MAX_BLOCK` (256) bytes per UPDI burst using a three-frame sequence per datasheet §35.3.3.4: (1) a pointer-set frame — `ST_PTR_WORD` (`0x69`) followed by the 16-bit target address in little-endian order when `addr ≤ 0xFFFF`, or `ST_PTR_LONG` (`0x6A`) followed by the 24-bit address in little-endian order when `addr > 0xFFFF` — with a single ACK readback; (2) `REPEAT` (`0xA0`) followed by `(block_len - 1)`; (3) `LD ptr++` (`0x24`) for reads or `ST ptr++` (`0x64`) for writes. The pointer-set frame shall always use the 24-bit `ST_PTR_LONG` (`0x6A`) form regardless of the requested address (see LLR-UPDI-33, which mandates the 24-bit form unconditionally to avoid the stale-high-byte hazard); the 16-bit `ST_PTR_WORD` (`0x69`) form is never used. The 24-bit form covers every address, including the AVR128DA/DB mapped-Flash region above 64 KiB. If `len` exceeds `UPDI_MAX_BLOCK`, the function shall split the request into consecutive bursts automatically, with no size restriction imposed on the caller.
    *Trace:* HLR-007 (Target Memory Read), HLR-008 (Target Memory Write).

*   <a id="LLR-UPDI-05"></a>**LLR-UPDI-05** — `updi_mem_read()` shall use `select()` with a 100 ms timeout before each `read()` call on the UART file descriptor to enforce a per-byte inactivity deadline. If `select()` returns zero (timeout) before a byte is available, the function shall abandon the current transaction and return -1.
    *Trace:* HLR-007 (Target Memory Read), HLR-037 (UPDI Operation Timeout Bounds).

*   <a id="LLR-UPDI-06"></a>**LLR-UPDI-06** — `updi_mem_write()` shall write arbitrary byte ranges to the SRAM address space of the target using UPDI ST commands and return 0 on success or -1 on UART framing error, timeout, or UPDI NAK.
    *Trace:* HLR-008 (Target Memory Write).

*   <a id="LLR-UPDI-07"></a>**LLR-UPDI-07** — `updi_nvm_write_flash()` shall require `word_addr` to be aligned to a 512-byte FLASH page boundary and `len` to be a non-zero multiple of 512. It shall enter NVM programming mode by transmitting the `KEY` opcode (`0xE0`) with the 8-byte string `"NVMProg "`, asserting reset with `STCS ASI_RESET_REQ = 0x59`, releasing reset with `STCS ASI_RESET_REQ = 0x00`, then polling `ASI_SYS_STATUS` via LDCS for bit 3 (NVMPROG, mask `0x08`) up to 100 iterations (≈ 100 ms). For each page it shall write the page data via `updi_mem_write()`, write `0x03` (ERWP) to `NVMCTRL_CTRLA`, and poll `NVMCTRL_STATUS` bit 0 (BUSY) clear up to 20 iterations (≈ 20 ms). On exit it shall toggle `ASI_RESET_REQ` `0x59` then `0x00` to release the target. Timeout of either poll shall return -1; a `NVMCTRL_STATUS` WRERR (bit 2) shall return `UPDI_ERR_WP`.
    *Trace:* HLR-009 (FLASH Programming), HLR-037 (UPDI Operation Timeout Bounds).

*   <a id="LLR-UPDI-08"></a>**LLR-UPDI-08** — `updi_halt()` shall halt the CPU by writing `ASI_OCD_CTRLA_STOP` (0x01) to `ASI_OCD_CTRLA` via STCS, then polling `ASI_OCD_STATUS` via LDCS for bit `ASI_OCD_STATUS_STOPPED` (0x01) set. The function shall return 0 once the STOPPED bit is observed and -1 on UPDI failure or if the bit does not become set within the LDCS poll budget.
    *Trace:* HLR-010 (Execution Control).

*   <a id="LLR-UPDI-09"></a>**LLR-UPDI-09** — `updi_step()` shall single-step the halted CPU by setting `OCD_CTRL0_STEP` (0x04) in `OCD_CTRL0` (UPDI byte address `0x0F88`) via STS, then writing `ASI_OCD_CTRLA_RUN` (0x02) to `ASI_OCD_CTRLA` via STCS to release the CPU for exactly one instruction, then polling `ASI_OCD_STATUS.STOPPED` until set. Returns 0 on success, -1 on UPDI failure.
    *Trace:* HLR-010 (Execution Control).

*   <a id="LLR-UPDI-10"></a>**LLR-UPDI-10** — `updi_run()` shall resume the halted CPU by writing `ASI_OCD_CTRLA_RUN` (0x02) to `ASI_OCD_CTRLA` via STCS and shall return 0 immediately without polling — callers that need to wait for a subsequent halt shall use `updi_ocd_poll_halted()` directly. Returns -1 on UPDI failure.
    *Trace:* HLR-010 (Execution Control).

*   <a id="LLR-UPDI-11"></a>**LLR-UPDI-11** — `updi_mem_read()` shall be callable while the target CPU is in the RUNNING state (not halted). The function shall not call `updi_halt()` internally, permitting non-intrusive SRAM sampling for the monitor sub-commands and console polling without interrupting firmware execution.
    *Trace:* HLR-011 (Non-Intrusive Background Memory Read).

*   <a id="LLR-UPDI-12"></a>**LLR-UPDI-12** — `updi_console_poll()` shall perform a background `updi_mem_read()` of the avrOS software UART output buffer and return any pending bytes to the caller without halting the CPU. The function shall return the number of bytes read (0 if none pending) or -1 on UPDI error.
    *Trace:* HLR-012 (UPDI Console Bridge).

*   <a id="LLR-UPDI-13"></a>**LLR-UPDI-13** — `updi_read_device_info(fd, info)` shall populate the caller-supplied `UpdiDeviceInfo` struct with: 3 SIGROW DEVICEID bytes from physical address `0x1100`-`0x1102` (datasheet §7.6.1, Table 7-4), the SYSCFG.REVID byte at `0x0F01` (datasheet §8.3.2.1; SYSCFG base `0x0F00`), 16 SERNUM bytes at `0x1110`-`0x111F` (datasheet §7.6.2.3), and the three ASI registers `ASI_SYS_STATUS`, `ASI_KEY_STATUS`, `ASI_STATUSB` read via `LDCS`. The function shall be non-destructive (no halt, no NVM activity). On any UPDI read failure it shall set `info->fail_op` to a short ASCII tag (`"sigrow"`, `"revid"`, `"sernum"`, `"sys-status"`, `"key-status"`, `"asi-statusb"`) and return -1; on success it shall set `info->fail_op = NULL` and return 0.
    *Trace:* HLR-044 (Device-Signature Diagnostic Mode).

*   <a id="LLR-UPDI-14"></a>**LLR-UPDI-14** — After each successful `LDCS ASI_STATUSA` link probe inside `updi_open()`, the function shall read the target's 32-byte System Information Block by transmitting `SYNCH` (`0x55`) followed by opcode `UPDI_OP_KEY_SIB` (`0xE6`) and reading exactly `UPDI_SIB_LEN` (32) bytes of response — looped over `read()` until the full block is collected. The SIB read serves two purposes: (1) it confirms the link end-to-end (target must be actively responding to return non-echo bytes), and (2) it wakes a target that was left in UPDI SLEEP from a prior debug session. Without this step a sleeping target will appear to accept every link-layer probe (STCS, LDCS) — those frames merely echo on the half-duplex line — yet reject every memory access, manifesting as `updi_mem_read()` returning -1 immediately after a successful `updi_open()`. avrdude's `serialupdi` issues this exact 32-byte SIB read on every connect; the response payload (e.g. `"    AVR P:2D:1-3M2 (A7.KV001.0)\0"`) is discarded by `updi_open()` since the caller currently only needs the wake side-effect. If the SIB read times out or returns fewer than 32 bytes the attempt shall be abandoned and the next cold-start attempt shall begin.
    *Trace:* HLR-006 (UPDI Hardware Connection), HLR-036 (UPDI Cold-Start Contention Handshake).

*   <a id="LLR-UPDI-15"></a>**LLR-UPDI-15** — `updi_enter_debug()` shall arm the AVR-Dx OCD by transmitting the UPDI `KEY` opcode (`0xE0`) followed by the 8-byte key string `"OCD     "` (ASCII `0x20 0x20 0x20 0x20 0x20 0x44 0x43 0x4F` — `"OCD"` reversed and right-padded with spaces, per the AVR-Dx datasheet KEY-string LSB-first convention), then pulsing `ASI_RESET_REQ` with `0x59` followed by `0x00`, then polling `ASI_OCD_STATUS` for the STOPPED bit. It shall be called once per session by `main.c` after `updi_open()` and before `rsp_listen()`. Returns 0 on success, -1 on UPDI failure or if STOPPED is never observed.
    *Trace:* HLR-010 (Execution Control).

*   <a id="LLR-UPDI-16"></a>**LLR-UPDI-16** — `updi_ocd_poll_halted(fd, timeout_ms)` shall poll `ASI_OCD_STATUS` via LDCS at ≈1 ms intervals until either `ASI_OCD_STATUS_STOPPED` (0x01) is set or `timeout_ms` elapses. Returns 0 if STOPPED is observed, +1 if the deadline elapses with the CPU still running, and -1 on UPDI failure. The RSP `c` handler uses this primitive with a short (≈1 ms) deadline to multiplex OCD polling with select() on the GDB client socket.
    *Trace:* HLR-010 (Execution Control), HLR-018 (Continue Execution).

*   <a id="LLR-UPDI-17"></a>**LLR-UPDI-17** — `updi_ocd_read_halt_status(fd, *st0, *st1)` shall read the two OCD halt-cause bytes from `OCD_STATUS0` (`0x0F8C`) and `OCD_STATUS1` (`0x0F8D`) via UPDI LDS and store them in the caller's buffers. The bits in `OCD_STATUS1` distinguish the halt cause: `OCD_STATUS1_EXTBRK` (0x10) is set when the CPU halted due to an external break (STOP via STCS or Ctrl-C), `OCD_STATUS1_BP1`/`BP0STEP`/`SWBP`/`JMP`/`INT` indicate hardware-breakpoint/step/BREAK-opcode/change-of-flow/interrupt halts. Returns 0 on success, -1 on UPDI failure.
    *Trace:* HLR-010 (Execution Control), HLR-018 (Continue Execution).

*   <a id="LLR-UPDI-18"></a>**LLR-UPDI-18** — `updi_ocd_read_gpr(fd, n, *val)` and `updi_ocd_write_gpr(fd, n, val)` shall read or write byte register `r<n>` (`n` in `0..31`) via UPDI LDS/STS to `OCD_REGFILE + n` (`0x0FA0 + n`). The CPU must be halted; behaviour against a running CPU is undefined. Returns 0 on success, -1 on UPDI failure or out-of-range `n`.
    *Trace:* HLR-014 (Register Read and Write).

*   <a id="LLR-UPDI-19"></a>**LLR-UPDI-19** — `updi_ocd_read_sreg(fd, *val)` and `updi_ocd_write_sreg(fd, val)` shall read or write the AVR status register via UPDI LDS/STS to `OCD_SREG` (`0x0F9C`). The CPU must be halted. Returns 0 on success, -1 on UPDI failure.
    *Trace:* HLR-014 (Register Read and Write).

*   <a id="LLR-UPDI-20"></a>**LLR-UPDI-20** — `updi_ocd_read_sp(fd, *val)` and `updi_ocd_write_sp(fd, val)` shall read or write the 16-bit AVR stack pointer (little-endian SPL|SPH) via UPDI LDS/STS at `OCD_SP` (`0x0F98`). `updi_ocd_read_pc(fd, *byte_addr)` and `updi_ocd_write_pc(fd, byte_addr)` shall read or write the 16-bit OCD program-counter register at `OCD_PC` (`0x0F94`), converting between the silicon's word-aligned PC+1 storage and the GDB byte address — read shifts the stored 16-bit word left by one and subtracts the AVR `+1` post-increment; write performs the inverse. The CPU must be halted. Returns 0 on success, -1 on UPDI failure.
    *Trace:* HLR-014 (Register Read and Write).

*   <a id="LLR-UPDI-21"></a>**LLR-UPDI-21** — `updi_ocd_set_hw_bp(fd, idx, byte_addr)` shall program hardware breakpoint comparator `idx` (0 or 1) to the supplied AVR byte address by writing the 3-byte little-endian address to `OCD_BP0A` (`0x0F80`) for slot 0 or `OCD_BP1A` (`0x0F84`) for slot 1 via UPDI STS, then setting the matching `OCD_CTRL1_BP0` / `OCD_CTRL1_BP1` enable bit and the global `OCD_CTRL0_HWBP` enable bit. Returns 0 on success, -1 on UPDI failure or invalid `idx`.
    *Trace:* HLR-016 (Breakpoints).

*   <a id="LLR-UPDI-23"></a>**LLR-UPDI-23** — `updi_nvm_write_eeprom(fd, addr, data, len)` shall write `len` bytes from `data` to the EEPROM window `[UPDI_EEPROM_BASE, UPDI_EEPROM_BASE + UPDI_EEPROM_SIZE)` (`0x814000`–`0x8143FF`). The function shall reject zero-length writes, an `addr` below the window, or `addr + len` past the window end with -1 and without issuing any UPDI traffic. It shall enter NVM programming mode via the standard NVMPROG KEY + reset pulse + `ASI_SYS_STATUS.NVMPROG` poll, then for each byte: (1) `STS NVMCTRL_CTRLA = EEERWR` (`0x13`); (2) `STS addr+i = data[i]`; (3) poll `NVMSTATUS.EEBUSY` (bit 1) clear up to 200 ms. After the final byte it shall write `NVMCTRL_CTRLA = NOCMD` to release the controller. Returns 0 on success, -1 on UPDI failure or BUSY timeout.
    *Trace:* HLR-046 (Non-FLASH NVM Programming), HLR-037 (UPDI Operation Timeout Bounds).

*   <a id="LLR-UPDI-24"></a>**LLR-UPDI-24** — `updi_nvm_write_userrow(fd, addr, data, len)` shall write the USERROW window `[UPDI_USERROW_BASE, UPDI_USERROW_BASE + UPDI_USERROW_SIZE)` (`0x810080`–`0x8100FF`, 128 bytes) using the identical NVMPROG + `EEERWR` per-byte sequence as LLR-UPDI-23, with `EEBUSY` polling between bytes. Out-of-window addresses or oversize writes shall return -1 without UPDI traffic. Returns 0 on success, -1 on failure.
    *Trace:* HLR-046 (Non-FLASH NVM Programming).

*   <a id="LLR-UPDI-25"></a>**LLR-UPDI-25** — `updi_nvm_write_fuses(fd, addr, data, len)` shall write the FUSES window `[UPDI_FUSES_BASE, UPDI_FUSES_BASE + UPDI_FUSES_SIZE)` (`0x820000`–`0x82001F`, 32 bytes) using the same NVMPROG + `EEERWR` per-byte sequence with `EEBUSY` polling. Out-of-window addresses or oversize writes shall return -1 without UPDI traffic. Returns 0 on success, -1 on failure.
    *Trace:* HLR-046 (Non-FLASH NVM Programming).

*   <a id="LLR-UPDI-26"></a>**LLR-UPDI-26** — `updi_nvm_write_lockbits(fd, addr, data, len, allow_updi_disable)` shall write the LOCK window `[UPDI_LOCK_BASE, UPDI_LOCK_BASE + UPDI_LOCK_SIZE)` (`0x820040`–`0x820043`, 4 bytes) using the same NVMPROG + `EEERWR` per-byte + `EEBUSY` poll sequence. Two safety interlocks gate the write: (a) it shall LDCS-read `ASI_SYS_STATUS` and return `UPDI_ERR_LOCKED` (-3) if `LOCKSTATUS` (bit 1, mask `0x02`) is asserted — the device must already have been chip-erased to clear LOCKSTATUS; (b) when `allow_updi_disable` is false and `len == 4`, it shall reject any payload whose little-endian 4-byte value is not the unlock pattern `UPDI_LOCK_UNLOCKED` (`0x5CC5C55C`), returning `UPDI_ERR_LOCKED` — this prevents accidentally setting bit patterns that would assert `UPDIDIS` and permanently disable the UPDI interface. Out-of-window addresses shall return -1 without UPDI traffic. Returns 0 on success, -1 on UPDI failure or BUSY timeout, `UPDI_ERR_LOCKED` on safety-interlock rejection.
    *Trace:* HLR-047 (Lockbit Programming Safety Interlock).

*   <a id="LLR-UPDI-22"></a>**LLR-UPDI-22** — `updi_ocd_clear_hw_bp(fd, idx)` shall disable hardware breakpoint comparator `idx` (0 or 1) by clearing the matching `OCD_CTRL1_BP0` / `OCD_CTRL1_BP1` enable bit via UPDI LDS/STS read-modify-write on `OCD_CTRL1` (`0x0F89`). The function shall not clear the global `OCD_CTRL0_HWBP` bit (the other comparator may still be armed). Returns 0 on success, -1 on UPDI failure or invalid `idx`.
    *Trace:* HLR-016 (Breakpoints).

*   <a id="LLR-UPDI-27"></a>**LLR-UPDI-27** — The UPDI module shall publish a `UpdiDeviceMap` struct (family name; USERROW base/size; EEPROM base/size; FUSES base/size; LOCK base/size; SIGROW base; `hw_tested` flag) and a static `g_device_table[]` with one entry per supported family populated from the published datasheet memory maps: AVR-DA (USERROW `0x1080`/32 B, EEPROM `0x1400`/512 B, SIGROW `0x1100`, hw-tested), AVR-DB (identical to DA, untested), AVR-DD (USERROW `0x1080`/128 B, EEPROM `0x1400`/256 B, SIGROW `0x1100`, untested), AVR-DU (USERROW `0x1200`/512 B, EEPROM `0x1400`/256 B, SIGROW `0x1080`, untested), AVR-SD (identical to AVR-DU, untested). FUSES `0x1050`/16 B and LOCK `0x1040`/4 B are identical across all five families. The module shall expose two entry points: (a) `int updi_select_device(int fd, const char *force_family)` — when `force_family` is non-NULL and non-empty, find the entry whose `family` matches `force_family` case-insensitively and set the module's `g_device` pointer to it (emitting a `stderr` warning when `hw_tested` is false); otherwise read SIGROW DEVICEID0..2 at the canonical address `0x1100` and look up the matching autodetect signature for AVR-DA/DB, returning -1 with a diagnostic that lists all five families and the `--force-device` option when DEVICEID0 is not `0x1E` or the signature is unknown; (b) `const UpdiDeviceMap *updi_get_device(void)` — return the current `g_device` pointer (defaulting to the AVR-DA entry so callers that bypass `updi_select_device()` still see the historical AVR-DA constants). All four NVM writer functions (`updi_nvm_write_eeprom`, `updi_nvm_write_userrow`, `updi_nvm_write_fuses`, `updi_nvm_write_lockbits`) shall obtain their window base and size from `updi_get_device()` rather than the compile-time `UPDI_*_BASE/_SIZE` macros. The USERROW writer shall use a stack buffer of size `UPDI_USERROW_ROW_LEN_MAX` (512 B, sized for AVR-DU/SD) and the actual row length from `dev->userrow_size`. Returns 0 on success, -1 on autodetect failure or unknown family name.
    *Trace:* HLR-048 (Multi-Family Runtime Device Dispatch), HLR-046 (Non-FLASH NVM Programming).

*   <a id="LLR-UPDI-28"></a>**LLR-UPDI-28** — The UPDI module shall publish `const char *updi_family_from_partname(const char *partname)`, a table-driven classifier that maps a lowercase Microchip AVR part-name string (the form emitted by the ELF `.note.gnu.avr.deviceinfo` note, e.g. `"avr128da28"`, `"avr64dd32"`, `"avr32sd20"`) onto one of the five family strings already published by `g_device_table[]`. The classifier shall accept the prefix `"avr"` followed by one or more ASCII digits (the flash-size field), followed by exactly two lowercase family-letters: `da`→`AVR-DA`, `db`→`AVR-DB`, `dd`→`AVR-DD`, `du`→`AVR-DU`, `sd`→`AVR-SD`. Any other input — `NULL`, the empty string, a string not beginning with `"avr<digit>"`, or a family-letter pair not in the table (notably `ea`/`eb`, which are the unsupported NVMCTRL v3 families) — shall return `NULL`, signalling the caller that the ELF carries no usable family identification and the SIGROW autodetect fallback in `updi_select_device()` must run. The classifier is intentionally co-located with `g_device_table[]` so that adding a new family requires updating both in the same commit.
    *Trace:* HLR-048 (Multi-Family Runtime Device Dispatch).

*   <a id="LLR-UPDI-29"></a>**LLR-UPDI-29** — `updi_nvm_read(fd, addr, buf, len)` shall read `len` bytes from the supplied UPDI unified-address `addr` into the caller-supplied `buf` using the existing `updi_mem_read()` block-transfer primitive (LLR-UPDI-04). It is a thin wrapper that exists so that Phase 9 verify and fuse-decode call sites read against an API named for the abstraction (NVM read) rather than the transport (UPDI memory read), and so it can be wrapped in unit tests independently of `updi_mem_read()`. The function shall not enter NVMPROG mode (NVM read does not require it) and shall not halt the CPU. Returns 0 on success, -1 on UPDI failure or timeout.
    *Trace:* HLR-049 (Read-Back Verify After Load), HLR-051 (Fuses Pretty-Printer in Device Mode).

*   <a id="LLR-UPDI-30"></a>**LLR-UPDI-30** — `updi_crc32(buf, len)` shall compute the IEEE 802.3 CRC-32 of the supplied byte buffer using the reflected polynomial `0xEDB88320`, an initial value of `0xFFFFFFFF`, and a final XOR with `0xFFFFFFFF`. The implementation shall be a portable bit-wise loop (no precomputed table) because it is invoked only on verify-mismatch paths where speed is not critical. The function is published purely for the verify diagnostic line so that operators can correlate read-back failures against externally computed checksums (e.g. `crc32 < file`). Returns the computed 32-bit checksum.
    *Trace:* HLR-049 (Read-Back Verify After Load).

*   <a id="LLR-UPDI-31"></a>**LLR-UPDI-31** — The UPDI module shall publish a `UpdiBaudReport` typedef carrying `int baud, int errors, int samples`, the candidate baud ladder `const int updi_baud_ladder[] = {230400, 200000, 150000, 115200, 57600, 38400, 19200}` with `updi_baud_ladder_count = 7`, and the probe function `int updi_probe_baud(const char *serial_device, int samples, void (*visitor)(const UpdiBaudReport *, void *), void *user)`. The probe shall, for each rung in `updi_baud_ladder[]` in order, open the UART at the candidate rate (full cold-start handshake per LLR-UPDI-02 not required — a minimal `updi_open()` is sufficient), issue exactly `samples` `LDCS ASI_STATUSA` probes, count as an error each probe whose response byte is negative (read failure) or whose upper nibble is zero (UPDIREV must be non-zero on a live link), close the UART, and invoke `visitor(&report, user)` with the captured `{baud, errors, samples}`. After walking the entire ladder the function shall return the first rung that observed zero errors (highest-rate first because the ladder is ordered high-to-low), or `-1` if no rung observed zero errors. The probe is read-only: it issues no STCS write, no NVM operation, no system-reset pulse, and does not call `updi_enter_debug()`.
    *Trace:* HLR-052 (Auto-Baud Link-Quality Probe in Device Mode).

*   <a id="LLR-UPDI-32"></a>**LLR-UPDI-32** — `updi_format_fuses(family, fuse_buf, fuse_len, lock_buf, lock_len, out, out_size)` shall format a human-readable decode of the supplied FUSES window and 4-byte LOCK window into the caller-supplied `out` buffer (NUL-terminated, truncating at `out_size - 1` characters). The decode shall consist of: (1) a header line `Fuses (<family>, <fuse_len> bytes):`; (2) for each byte covered by the per-family fuse table, one indented line `  0x%02X  <FUSE_NAME>%-22s = 0x%02X` followed by indented sub-lines naming each documented bit-field with human-readable enum names (e.g. `WDTCFG.PERIOD = 8K`); (3) for each fuse byte without a registered decoder, one indented line `  0x%02X  (reserved) raw=0x%02X`; (4) a final line `Lock: 0x%08X (UNLOCKED|LOCKED)` where `UNLOCKED` is the canonical 4-byte little-endian value `UPDI_LOCK_UNLOCKED = 0x5CC5C55C` and any other value is reported as `LOCKED`. The decoder tables (`FuseField` struct and `g_avr_dx_fuses[]`) shall live alongside `g_device_table[]` in `src/updi.c` so they are selected by the same `updi_select_device()` runtime path. Phase 9 ships the AVR-DA/AVR-DB table; for other families the function shall emit only the reserved-style lines for every byte (no bit-field decoding). Returns the number of bytes written to `out` (excluding the terminating NUL).
    *Trace:* HLR-051 (Fuses Pretty-Printer in Device Mode).

*   <a id="LLR-UPDI-33"></a>**LLR-UPDI-33** — `updi_set_ptr(fd, addr)` shall ALWAYS set the UPDI burst pointer with the 24-bit `ST_PTR_LONG` (`0x6A`) form — `SYNCH`, `ST_PTR_LONG`, `addr` bytes 0..2 in little-endian order, single ACK — for every address, including addresses ≤ 0xFFFF. The 16-bit `ST_PTR_WORD` (`0x69`) form shall never be used. Rationale: `ST_PTR_WORD` updates only the low two pointer bytes and leaves the high byte (bits 16..23) at whatever a previous `ST_PTR_LONG` left it. AVR-Dx mapped-Flash reads set that high byte to `0x80`, so a following 16-bit SRAM read (UPDI `0x004000..0x007FFF`) was misdirected to `0x80xxxx` (mapped Flash) and returned erased `0xFF` on a sparsely-programmed part. Because GDB interleaves Flash reads (code and line tables) with stack reads, this surfaced as intermittently garbage local-variable values and bogus `0x1fffe` backtraces whenever a Flash read preceded a stack read. Emitting the full 24-bit pointer on every pointer-set removes the stale-high-byte hazard (this is also what avrdude's `serialupdi` does). Verified on hardware: an interleaved 16-bit-vs-24-bit A/B test in the same fault window was 0/12 vs 12/12 correct.
    *Trace:* HLR-007 (Target Memory Read), HLR-008 (Target Memory Write).

## 4. src/gdb_rsp.c — GDB Remote Serial Protocol Server

Requirements for RSP packet framing, dispatch, GDB packet handlers, session lifecycle, and socket configuration.

*   <a id="LLR-RSP-01"></a>**LLR-RSP-01** — `rsp_listen()` shall set `SO_REUSEADDR` on the listener socket before calling `bind()`. After `rsp_accept()` returns a connected client socket, the client socket shall have `TCP_NODELAY` set to disable Nagle's algorithm.
    *Trace:* HLR-003 (GDB Listener Startup), HLR-038 (GDB Session Response Latency).

*   <a id="LLR-RSP-02"></a>**LLR-RSP-02** — `rsp_recv_packet()` shall scan incoming bytes discarding pre-packet ACK/NAK characters until a `$` delimiter is received. It shall accumulate the payload with a running XOR checksum until `#` is received, then compare the computed checksum against the two ASCII-hex checksum bytes that follow. On match it shall write `+` to the socket and return the payload length; on mismatch it shall write `-` and return -1.
    *Trace:* HLR-013 (RSP Server Accessibility).

*   <a id="LLR-RSP-03"></a>**LLR-RSP-03** — The `on_read_regs` handler for the `g` packet shall produce a 78-character hex string in GDB's AVR register-block layout: R0-R31 at hex positions 0-63, SREG at 64-65, SPL at 66-67, SPH at 68-69, and PC as 4-byte little-endian byte-address at positions 70-77. All `g` reads shall use the live OCD register file via `updi_ocd_read_gpr()`, `updi_ocd_read_sreg()`, `updi_ocd_read_sp()`, and `updi_ocd_read_pc()` — the live CPU is the sole GDB thread.
    *Trace:* HLR-014 (Register Read and Write).

*   <a id="LLR-RSP-04"></a>**LLR-RSP-04** — The `on_write_regs` handler shall accept both the full-register `G<78 hex>` and single-register `P<n>=<hex>` packets and shall route each register slot to the matching OCD writer: `updi_ocd_write_gpr()` for registers 0..31, `updi_ocd_write_sreg()` for register 32, `updi_ocd_write_sp()` for register 33 (little-endian 16-bit), and `updi_ocd_write_pc()` for register 34 (little-endian 32-bit byte-address). On success the handler shall reply `OK`; on any OCD failure or hex parse error it shall reply `E01`.
    *Trace:* HLR-014 (Register Read and Write).

*   <a id="LLR-RSP-05"></a>**LLR-RSP-05** — The `on_read_mem` handler for `m addr,len` shall translate the GDB unified-address `addr` to a UPDI physical address by flipping bit 23 (GDB FLASH at `< 0x800000` maps to UPDI `0x800000+`; GDB data space at `>= 0x800000` maps to UPDI `0x000000+`), then call `updi_mem_read()` and return the result as a hex string. Both FLASH and SRAM addresses shall be accepted.
    *Trace:* HLR-015 (Memory Read and Write).

*   <a id="LLR-RSP-06"></a>**LLR-RSP-06** — The `on_write_mem` handler for `M addr,len:data` (hex-encoded) and `X addr,len:data` (binary-encoded) packets shall route by the GDB address space: writes with bit 23 set (data space) shall go to `updi_mem_write()` against the GDB-byte address with bit 23 cleared; writes with bit 23 clear (program space) shall go to `updi_nvm_write_flash()` against the GDB address OR'd with `UPDI_FLASH_BASE` (`0x800000`). Returns `OK` on success, `E01` on failure.
    *Trace:* HLR-015 (Memory Read and Write).

*   <a id="LLR-RSP-07"></a>**LLR-RSP-07** — The `on_insert_bp` handler for `Z0` and `Z1` shall route both kinds to the same two AVR-Dx OCD hardware comparators tracked by `RspContext.hw_bp_addr[0..1]`. If the supplied address is already present in either slot the handler shall reply `OK` without re-programming silicon. Otherwise the handler shall find an empty slot (sentinel `0xFFFFFFFF`), call `updi_ocd_set_hw_bp()` with the GDB-byte address masked to 23 bits, record the address in the shadow, and reply `OK`. The handler shall not call `updi_nvm_write_flash()` — patching the AVR BREAK opcode into FLASH at runtime is incompatible with maintaining live OCD register state.
    *Trace:* HLR-016 (Breakpoints).

*   <a id="LLR-RSP-08"></a>**LLR-RSP-08** — The `on_remove_bp` handler for `z0` and `z1` shall locate the supplied address in `RspContext.hw_bp_addr[0..1]`, call `updi_ocd_clear_hw_bp()` for that slot, reset the slot to the empty sentinel, and reply `OK`. If the address is not present in either slot (e.g. the server has been restarted mid-session and lost the shadow) the handler shall reply `OK` rather than an error so a GDB resync after reconnect is non-fatal.
    *Trace:* HLR-016 (Breakpoints).

*   <a id="LLR-RSP-09"></a>**LLR-RSP-09** — When `on_insert_bp` is called and the single user `RspContext.hw_bp_addr[]` slot (slot 0) is occupied, and the requested address does not match that slot, the handler shall not call `updi_ocd_set_hw_bp()` and shall reply with the GDB error packet `E08`. This surfaces the fact that although AVR-Dx has two comparators, one is permanently reserved for the 32-bit stepping errata workaround, leaving exactly one hardware breakpoint slot available for the user.
    *Trace:* HLR-016 (Breakpoints).

*   <a id="LLR-RSP-10"></a>**LLR-RSP-10** — The `on_step` handler for `s`/`vCont;s` shall read the current PC and the corresponding opcode. If the instruction is a 32-bit `CALL`, `JMP`, `LDS` or `STS`, it shall calculate the target PC of the next instruction, install a temporary hardware breakpoint at that target PC using `BP1` (slot 1), call `updi_run()` and await a halt, then immediately clear the `BP1` comparator. Otherwise, it shall call `updi_step()`. In either case, it subsequently invalidates the FSM thread cache, rebuilds the thread list, and then replies with the stop-reason packet `T<sig>thread:<active_id>;` produced by the `on_halt_reason` handler. The signal returned by `signal_for_halt_status()` shall be `T02` (SIGINT) if `OCD_STATUS1.EXTBRK` is observed (e.g. the step landed back inside a software-halt window) and `T05` (SIGTRAP) otherwise.
    *Trace:* HLR-017 (Single-Step Execution).

*   <a id="LLR-RSP-11"></a>**LLR-RSP-11** — The `on_continue` handler for `c`/`vCont;c` shall, before resuming, call the `continue_step_over_leading_cof(ctx)` helper to compensate for the AVR-Dx OCD "first change-of-flow after RUN" errata (issue #40, HLR-062): the helper reads the live PC via `updi_ocd_read_pc()` and the 4 opcode bytes at that PC via `updi_mem_read(fd, pc | UPDI_FLASH_BASE, buf, 4)`, and — if the instruction is a direct 32-bit `CALL` (`(w0 & 0xFE0E) == 0x940E`) or `JMP` (`(w0 & 0xFE0E) == 0x940C`), decoding the branch target `k = w1 | ((w0 & 0x0001) << 16) | (((w0 & 0x01F0) >> 4) << 17)` — emulates the change-of-flow over OCD via `updi_ocd_emulate_cof_32bit()` (return address `pc + 4` pushed for `CALL`, `0` i.e. no push for `JMP`; branch byte target `k * 2`) so the subsequent free-run resumes at a non-CoF instruction. 16-bit change-of-flow (`RJMP`/`RCALL`/branches/`RET`/`ICALL`) and the resume-from-SW-BREAK case read back as non-matching opcodes and fall through to a plain run unchanged. The helper returns 0 (with or without an emulation) or -1 on UPDI error, in which case the handler replies `E01`. The handler shall then call `updi_run()` and `fsm_invalidate()`, then enter a poll loop that waits for either (a) a spontaneous CPU halt detected by `updi_ocd_poll_halted()` or (b) an async-interrupt byte (`\x03`) on the GDB client socket. The loop shall multiplex the two events using `select()` with a 5 ms timeout on the client socket; on socket-readable it shall consume one byte and break on `0x03`; on select-timeout it shall poll OCD with a 1 ms deadline. After the loop breaks the handler shall call `updi_halt()` to guarantee the CPU is stopped, rebuild the FSM thread list, and reply with `T02thread:<id>;` if Ctrl-C was received or `T05thread:<id>;` otherwise. The handler shall give up after `UPDI_FAIL_MAX` (8) consecutive `updi_ocd_poll_halted()` failures and reply `E01` rather than spinning indefinitely on a degraded UPDI link.
    *Trace:* HLR-018 (Continue Execution), HLR-062 (swbreak/hwbreak Stop-Cause Tags).

*   <a id="LLR-RSP-12"></a>**LLR-RSP-12** — `rsp_dispatch()` shall handle the following packets inline without invoking any `RspHandlers` slot, because each response is a fixed string requiring no target interaction: `qSupported` (responds with `PacketSize=800;QStartNoAckMode+;multiprocess-;vContSupported+`), `qAttached` (responds `1`), `QStartNoAckMode` (calls `rsp_set_noack(true)` and responds `OK`), and `vCont?` (responds `vCont;c;s`).
    *Trace:* HLR-019 (RSP Capability Negotiation and Lifecycle).

*   <a id="LLR-RSP-13"></a>**LLR-RSP-13** — The `on_detach` handler for the `D` packet shall release both AVR-Dx OCD hardware-breakpoint comparators by calling `updi_ocd_clear_hw_bp()` for every occupied `RspContext.hw_bp_addr[]` slot and resetting the shadow to the empty sentinel, then call `updi_run()` to resume the target, send the `OK` reply, close the GDB client socket, and reset `*ctx->gdb_fd_p` to -1 so the event loop re-enters the listening state. The server process shall not exit. Without the comparator cleanup, BP0/BP1 remain armed in silicon and the next GDB session inherits stale breakpoints from the previous client.
    *Trace:* HLR-016 (Breakpoints), HLR-019 (RSP Capability Negotiation and Lifecycle).

*   <a id="LLR-RSP-14"></a>**LLR-RSP-14** — The `on_detach` handler for the `k` (kill) packet shall set `g_quit = 1` to cause the event loop to exit, triggering the full resource teardown sequence defined by LLR-MAIN-07.

*   <a id="LLR-RSP-16"></a>**LLR-RSP-16** — The `H` (set-thread) packet handler shall store the requested GDB thread ID in the session context. The live CPU is the sole GDB thread (TID 1); thread IDs -1 (all threads) and 0 (any thread) shall both be interpreted as the live-CPU thread. Register and memory operations always target the live CPU.
    *Trace:* HLR-025 (Active Thread Identification).

*   <a id="LLR-RSP-17"></a>**LLR-RSP-17** — The `signal_for_halt_status()` helper shall read `OCD_STATUS0`/`OCD_STATUS1` via `updi_ocd_read_halt_status()` and return the stop-signal string `"T02"` (SIGINT) if `OCD_STATUS1_EXTBRK` (0x10) is set in `OCD_STATUS1`, or `"T05"` (SIGTRAP) otherwise (covering hardware-breakpoint match, BREAK opcode, single-step, change-of-flow, and interrupt halts). *   <a id="LLR-RSP-18"></a>**LLR-RSP-18** — The `hw_bp_clear_all(ctx)` helper shall check `ctx->hw_bp_addr[0]` and, if it is not equal to the empty sentinel (`0xFFFFFFFF`), call `updi_ocd_clear_hw_bp()` and reset the slot. *   <a id="LLR-RSP-19"></a>**LLR-RSP-19** — The `dh_query_c()` default handler (`qC`) shall reply with `QC<hex>` where `<hex>` is the lowercase-hexadecimal GDB thread id currently selected for `c`/`s` operations (the most recent `Hc<tid>` value, stored at `*ctx->c_thread_p`). *   <a id="LLR-RSP-21"></a>**LLR-RSP-21** — The `dh_thread_alive()` default handler (`T<tid>`) shall parse `<tid>` as a hexadecimal GDB thread id and reply `OK` when the id is present in `ctx->fsm->threads[].gdb_id` (with `ctx->fsm->valid == true`), `E01` otherwise. When the FSM context is unset or invalid the handler shall accept thread id `1` only (the default active thread on a freshly-attached session) and reject all others with `E01`. *   <a id="LLR-RSP-22"></a>**LLR-RSP-22** — The `dh_restart()` default handler (`R<XX>`) shall implement the extended-remote restart semantics by: (1) calling `updi_enter_debug()` to pulse `ASI_RESET_REQ` and re-enter OCD halted at the reset vector, replying `E01` and returning if the UPDI primitive fails; (2) calling `fsm_invalidate()` to drop the stale virtual-thread cache; and (3) delegating to `dh_continue()` with a synthetic `c` packet so the target resumes, the thread list is rebuilt on the next halt, and the resulting stop-reply packet is emitted to GDB. The `<XX>` byte of the inbound packet shall be ignored per the GDB protocol.
    *Trace:* HLR-059 (Protocol Cleanup — qC, qOffsets, T, R).

*   <a id="LLR-RSP-23"></a>**LLR-RSP-23** — The `dh_vrun()` default handler (`vRun;[<filename>][;<arg>...]`) shall implement extended-remote start-new-program by ignoring the filename and argument list (the target program is already in FLASH and there is no host-side filesystem), then performing a reset-and-halt-at-entry sequence: call `updi_enter_debug()` (reply `E01` on failure) to halt the CPU at the reset vector, call `fsm_invalidate()`, call `fsm_build_thread_list()` to rebuild the per-FSM thread cache, and delegate to `dh_halt_reason()` (`?`) to emit a `T05` stop reply. Per the GDB Remote Serial Protocol, `vRun` must return a stop reply immediately — the client decides when to start execution via its own `c` / `s` packets; the handler must NOT call `updi_run()` or otherwise resume the CPU.
    *Trace:* HLR-058 (Extended-remote — multiprocess+, vRun, vAttach, vKill).

*   <a id="LLR-RSP-24"></a>**LLR-RSP-24** — The `dh_vattach()` default handler (`vAttach;<pid>`) shall implement extended-remote attach by ignoring `<pid>` (the AVR target has no process namespace), then: (1) calling `updi_enter_debug()` to halt the running target and re-enter OCD, replying `E01` on UPDI failure; (2) calling `fsm_invalidate()` and `fsm_build_thread_list()` so virtual-thread state is fresh; and (3) delegating to `dh_halt_reason()` to emit a SIGTRAP stop reply containing the active `thread:<hex>;` so GDB knows the target is halted and ready for register and memory queries.
    *Trace:* HLR-058 (Extended-remote — multiprocess+, vRun, vAttach, vKill).

*   <a id="LLR-RSP-25"></a>**LLR-RSP-25** — The `dh_vkill()` default handler (`vKill[;<pid>]`) shall close the current GDB session without terminating the avrOSdb process. It shall ignore `<pid>` and, in order: (1) call `updi_halt()` on the target so the next attached session sees a stopped CPU; (2) release both AVR-Dx OCD HW-breakpoint comparators via `rsp_hw_bp_clear_all(ctx)`; (3) clear the per-session SW-breakpoint shadow via `rsp_sw_bp_clear_all(ctx)`; (4) reply `OK` to the client; (5) set `ctx->disconnect_reason = "vKill"` so `event_loop()` emits the lifecycle log line per LLR-MAIN-22; (6) close `*ctx->gdb_fd_p` (when ≥ 0) and set the pointed-at fd to `-1`. The handler shall **not** set `*ctx->quit_p`. This makes vKill a per-session disconnect (HLR-064) rather than a server-shutdown command; the legacy `k` packet path in `dh_detach` retains the old quit behaviour for operators relying on it.
    *Trace:* HLR-058 (Extended-remote — multiprocess+, vRun, vAttach, vKill), HLR-064 (vKill Listener Survival).

*   <a id="LLR-RSP-26"></a>**LLR-RSP-26** — The inline `qSupported` reply shall be the literal string `PacketSize=800;QStartNoAckMode+;multiprocess+;vContSupported+;vRun+;vAttach+;vKill+`. The `multiprocess+` feature is advertised even though the AVR target supports only a single process — it informs GDB that the server understands `<pid>.<tid>` thread-id syntax and accepts the extended-remote `v*` packets. `vRun+`, `vAttach+`, and `vKill+` advertise the corresponding handlers added by HLR-058. The inbound `vAttach?` capability probe shall be answered with `OK`.
    *Trace:* HLR-058 (Extended-remote — multiprocess+, vRun, vAttach, vKill).

*   <a id="LLR-RSP-27"></a>**LLR-RSP-27** — The `dh_insert_bp()` handler shall recognise the GDB watchpoint request prefixes `Z2`, `Z3`, and `Z4` and reply with the empty RSP packet (payload of length zero, on-the-wire `$#00`). The `dh_remove_bp()` handler shall do the same for `z2`, `z3`, and `z4`. The empty reply is the documented RSP signal for "feature unsupported" and causes GDB to silently fall back to software watchpoints. No call into the UPDI layer is made; no shadow state is consulted or updated; and no `qSupported` capability advertises watchpoints.
    *Trace:* HLR-056 (GDB watchpoints (Z2/Z3/Z4)).

*   <a id="LLR-RSP-32"></a>**LLR-RSP-32** — The `dh_vflash_erase()` default handler (`vFlashErase:<addr>,<length>`) shall parse the two hex fields and refuse with `E22` if either is malformed, `length` is zero, or any address in the range `[addr, addr+length)` has the data-space flag set (i.e. `(addr | (addr+length-1)) & GDB_AVR_DATA_FLAG`) — this rejects EEPROM, USERROW, FUSES, LOCK, and SIGROW windows since `gdb load` provides no per-window verb. Lengths larger than 1 MB shall also be refused with `E22` as a runaway-allocation guard. On success the handler shall (re-)allocate `RspContext.flash_xact_buf` to span the page-aligned union of any prior erased range and `[floor_page(addr), ceil_page(addr+length))`, pre-filling new pages with `0xFF`, and reply `OK`. Erase-on-silicon is deferred until `dh_vflash_done()` because `updi_nvm_write_flash()` performs an FLPER per page before each FLWR.
    *Trace:* HLR-053 (Flash Programming via GDB load).

*   <a id="LLR-RSP-33"></a>**LLR-RSP-33** — The `dh_vflash_write()` default handler (`vFlashWrite:<addr>:<binary>`) shall refuse with `E22` (and discard any in-progress page buffer) if no `vFlashErase` is active, the address is malformed, the address has the data-space flag set, or the address is below `RspContext.flash_xact_base`. Otherwise it shall decode RSP binary-protocol escapes (`0x7D <b>` → `b XOR 0x20`) in the payload and copy the resulting bytes into `flash_xact_buf` at offset `addr - flash_xact_base`, replying `E22` on buffer overflow and `OK` on success. The payload byte count is derived from the `plen` argument threaded through `rsp_dispatch_n()` so embedded NUL bytes do not truncate the copy.
    *Trace:* HLR-053 (Flash Programming via GDB load).

*   <a id="LLR-RSP-34"></a>**LLR-RSP-34** — The `dh_vflash_done()` default handler (`vFlashDone`) shall (a) if no transaction is active, reply `OK` immediately (treating the packet as a no-op); (b) otherwise call `updi_nvm_write_flash(updi_fd, UPDI_FLASH_BASE + flash_xact_base, flash_xact_buf, flash_xact_len)`, freeing the buffer and clearing `flash_xact_base/len` regardless of outcome, then reply `E22` on UPDI failure or — on success — call `rsp_hw_bp_clear_all()` (because the FLASH word at each shadowed HW-BP address may have been overwritten by the load), call `updi_enter_debug()` to leave the CPU halted at reset, and reply `OK`. Any `g`/`G`/`P`/`m`/`M`/`X`/`c`/`s` packet that arrives between `vFlashErase` and `vFlashDone` shall be rejected with `E22` by `rsp_dispatch_n()` and the in-progress page buffer shall be discarded.
    *Trace:* HLR-053 (Flash Programming via GDB load).

*   <a id="LLR-RSP-35"></a>**LLR-RSP-35** — The `qSupported` inline reply shall additionally advertise `vFlashErase+;vFlashWrite+;vFlashDone+` so GDB enables the `vFlash*` flow for the `load` command. The length-carrying `rsp_dispatch_n(fd, packet, plen, handlers)` entry point shall be the public dispatch API used by the main event loop; the legacy `rsp_dispatch()` shall remain as a thin wrapper that derives `plen` from `strlen(packet)`, for tests and any caller that knows the packet is ASCII-only.
    *Trace:* HLR-053 (Flash Programming via GDB load).

*   <a id="LLR-RSP-36"></a>**LLR-RSP-36** — The `dh_insert_bp()` default handler shall route `Z0,<addr>[,<kind>]` to a software-breakpoint installer when `ctx->bp_mode == RSP_BP_MODE_SW` (the default) and to the legacy hardware-comparator path when `ctx->bp_mode == RSP_BP_MODE_HW_ONLY` (per HLR-055 `monitor bp-mode hw-only`). Addresses with the `GDB_AVR_DATA_FLAG` (0x800000) bit set — EEPROM, USERROW, FUSES, LOCK, SIGROW — shall be refused with `E22` because the AVR `BREAK` opcode is only meaningful when fetched from FLASH. A duplicate `Z0` on an address already shadowed shall reply `OK` without re-patching. When all `RSP_MAX_SW_BREAKPOINTS` (64) shadow slots are occupied the handler shall reply `E08`. Z1 packets continue to alias to the two OCD HW comparators regardless of `bp_mode` (HLR-016).

*   <a id="LLR-RSP-37"></a>**LLR-RSP-37** — The SW-BP install path shall, for each `Z0` accepted in `RSP_BP_MODE_SW`, (1) snapshot R0–R31 via `updi_ocd_read_gpr()`, SREG via `updi_ocd_read_sreg()`, SP via `updi_ocd_read_sp()`, and PC via `updi_ocd_read_pc()`; (2) read the 2-byte original opcode at `UPDI_FLASH_BASE + (addr & GDB_AVR_ADDR_MASK)` via `updi_mem_read()`; (3) write `{0x98, 0x95}` (`BREAK` opcode, little-endian) to the same FLASH word via `updi_nvm_flash_patch()`; (4) call `updi_enter_debug()` to leave NVMPROG and re-enter OCD; (5) restore R0–R31, SREG, SP, and PC via the matching `updi_ocd_write_*()` primitives; and (6) record `(addr, orig[0], orig[1], in_use=true)` in the first free `RspContext.sw_bp[]` slot. Any UPDI link error during the sequence shall cause the handler to reply `E01` without partially populating the shadow slot.
    *Trace:* HLR-054 (True Software Breakpoints via Flash BREAK Opcode).

*   <a id="LLR-RSP-38"></a>**LLR-RSP-38** — The `dh_remove_bp()` default handler, on `z0,<addr>` in `RSP_BP_MODE_SW`, shall scan `ctx->sw_bp[]` for a slot whose `addr` matches and, when found, repeat the snapshot/patch/restore sequence of LLR-RSP-37 — writing the saved `orig[0..1]` bytes back to FLASH at `UPDI_FLASH_BASE + (addr & GDB_AVR_ADDR_MASK)` — then mark the slot `in_use=false` and reply `OK`. When no SW shadow slot matches, the handler shall fall through to the HW-comparator removal path so a `z0` after a `monitor bp-mode` toggle still drains both shadow tables. *   <a id="LLR-RSP-39"></a>**LLR-RSP-39** — The helper `rsp_sw_bp_clear_all(RspContext *ctx)` shall clear every entry in `ctx->sw_bp[]` (`in_use=false`, `addr=0`, `orig[0]=orig[1]=0`) without issuing any UPDI I/O. *   <a id="LLR-RSP-44"></a>**LLR-RSP-44** — `gdb_rsp.c` shall define a private `enum RspStopCause { SC_NONE = 0, SC_SWBREAK, SC_HWBREAK, SC_STEP, SC_INTR }` and a private function `static int classify_stop_cause(RspContext *ctx, int hint)` that returns one of those values. Callers pass `SC_INTR` from the `dh_continue` path when `got_ctrl_c` is set, `SC_STEP` from the `dh_step` path, and `SC_NONE` from the bare `?` (`dh_halt_reason`) and `vRun` / `vAttach` delegated paths. *   <a id="LLR-RSP-45"></a>**LLR-RSP-45** — The `qSupported` reply emitted by `rsp_dispatch()` shall append the literal substring `;swbreak+;hwbreak+` to the existing capability list, immediately after `vFlashDone+`. SC_INTR : SC_NONE)` immediately before formatting; `dh_step()` shall set it to `classify_stop_cause(ctx, SC_STEP)`; `dh_halt_reason()` shall set it to `classify_stop_cause(ctx, SC_NONE)` if it has not already been set by the previous-packet path. *   <a id="LLR-RSP-46"></a>**LLR-RSP-46** — `rsp_dispatch()` shall recognise packets that begin with the literal prefix `vCont;r` (after the seven-byte `vCont;r` and before any `:<thread>` suffix) and route them to a new private handler `static int dh_range_step(int fd, const char *pkt, void *vctx)`. SC_INTR : SC_STEP); return format_stop_reply(fd, ctx, got_ctrl_c ? 2 : 5, ctx->last_stop_cause);`. The `vCont?` reply shall be extended from `"vCont;c;s"` to `"vCont;c;s;r"`. The handler shall live alongside `dh_continue` / `dh_step` in `src/gdb_rsp.c` and shall not be added to the `RspHandlers` vtable (the dispatcher invokes it directly because it has no per-test override use case).
    *Trace:* HLR-066 (vCont;r Range Step).

*   <a id="LLR-RSP-47"></a>**LLR-RSP-47** — `rsp_dispatch()` shall recognise packets that begin with the literal prefix `qXfer:memory-map:read::` (23 bytes) and route them to a new private handler `static int dh_qxfer_memory_map(int fd, const char *pkt, void *vctx)`. The qSupported reply (currently `"PacketSize=800;QStartNoAckMode+;multiprocess+;vContSupported+;vRun+;vAttach+;vKill+;vFlashErase+;vFlashWrite+;vFlashDone+;swbreak+;hwbreak+"`) shall be extended with the suffix `";qXfer:memory-map:read+"`. The handler shall: (1) `strtoul()` two hex fields `<offset>,<length>` immediately after the prefix and reply `E00` on a missing comma or non-hex digits; (2) when both `ctx->flash_size == 0` and `ctx->sram_size == 0`, reply `l` (end-of-transfer with no data) so GDB falls back to its built-in defaults; (3) otherwise render an XML document into a stack `char xml[1024]` via a `snprintf()`-driven append loop, emitting the regions in this order — wrapped in `<memory-map>...</memory-map>`: `<memory type="flash" start="0x0" length="<flash_size>"><property name="blocksize">0x200</property></memory>` (Flash, only when `ctx->flash_size != 0`); `<memory type="ram" start="<sram_base>" length="<sram_size>"/>` (SRAM, only when `ctx->sram_size != 0`); EEPROM at `ELF_VMA_EEPROM = 0x810000` length `UPDI_EEPROM_SIZE = 0x200` typed `flash` blocksize `0x1`; FUSES at `ELF_VMA_FUSES = 0x820000` length `UPDI_FUSES_SIZE = 0x10` typed `flash` blocksize `0x1`; LOCK at `ELF_VMA_LOCK = 0x830000` length `UPDI_LOCK_SIZE = 0x4` typed `flash` blocksize `0x1`; SIGROW at `ELF_VMA_SIGROW = 0x840000` length `UPDI_SIGROW_SIZE = 0x40` typed `rom` (no blocksize child); USERROW at `ELF_VMA_USERROW = 0x850000` length `UPDI_USERROW_SIZE = 0x20` typed `flash` blocksize `0x20`. The five non-FLASH NVM regions are emitted unconditionally whenever the all-zero short-circuit at step (2) does not fire. On `snprintf` overflow the handler shall reply `E01`. (4) Slice `xml[offset, offset+length)` into the reply, prefix with `'l'` when the slice reaches end-of-document or `'m'` otherwise, and emit via `rsp_send_packet()`; offsets at or past the document length shall reply `l` with no payload. `RspContext` shall gain three sibling fields `uint32_t flash_size; uint32_t sram_base; uint32_t sram_size;` (declared adjacent to `last_stop_cause` in `src/gdb_rsp.h`); `src/main.c` shall populate them from `elf_ctx.flash_size` / `.sram_base` / `.sram_size` at the same designated-initialiser site that already sets `.idx`. The handler shall be inlined into `rsp_dispatch()` (sibling of the `qSupported` / `qAttached` inline routes, before the `case 'q':` switch arm) and shall not consume a `RspHandlers` vtable slot.
    *Trace:* HLR-063 (qXfer:memory-map:read+ Advertisement).

*   <a id="LLR-RSP-49"></a>**LLR-RSP-49** — `rsp_recv_packet()` and `rsp_send_packet()` shall check a file-scoped boolean flag `g_log_rsp`. If true, `rsp_recv_packet()` shall output `RSP < <packet>` to `stderr` after receipt, and `rsp_send_packet()` shall output `RSP > <packet>` to `stderr` before sending. The flag shall be mutated via a new `rsp_set_logging(bool)` setter exposed in `gdb_rsp.h`.
    *Trace:* HLR-068 (Detailed RSP Traffic Logging).

*   <a id="LLR-RSP-48"></a>**LLR-RSP-48** — `dh_read_mem()` shall, immediately after parsing and length-validating the `m<addr>,<len>` packet (and before the GDB↔UPDI bit-23 address translation), call a new file-private helper `static bool mm_range_in_advertised_region(const RspContext *ctx, uint32_t addr, uint32_t len)` and, when the helper returns `false`, return `reply_err(fd, "E14")` instead of invoking `updi_mem_read()`. The helper shall return `false` for `len == 0` or when the 32-bit sum `addr + len` wraps; it shall return `true` when both `ctx->flash_size == 0` and `ctx->sram_size == 0` (no memory map advertised — permissive fallback for HLR-063's no-ELF case); otherwise it shall return `true` iff the half-open range `[addr, addr+len)` lies entirely within one of these seven regions (using the same constants HLR-063's advertisement emits): `[0, ctx->flash_size)` when `flash_size != 0`; `[ctx->sram_base, ctx->sram_base + ctx->sram_size)` when `sram_size != 0`; `[ELF_VMA_EEPROM, ELF_VMA_EEPROM + UPDI_EEPROM_SIZE)`; `[ELF_VMA_FUSES, ELF_VMA_FUSES + UPDI_FUSES_SIZE)`; `[ELF_VMA_LOCK, ELF_VMA_LOCK + UPDI_LOCK_SIZE)`; `[ELF_VMA_SIGROW, ELF_VMA_SIGROW + UPDI_SIGROW_SIZE)`; `[ELF_VMA_USERROW, ELF_VMA_USERROW + UPDI_USERROW_SIZE)`. The helper shall be defined immediately above `dh_read_mem()` in `src/gdb_rsp.c` and shall be `static` (file scope) so it is exclusively callable from the `m`-read path. The check shall NOT be wired into `dh_write_mem()` for this requirement — symmetric write enforcement is deferred. UPDI shall not be touched on a bounds rejection (`mock_read_count` MUST remain 0 in the negative unit test).
    *Trace:* HLR-067 (Memory-Map Honesty for `m`-Reads).

## 5. src/elf_parser.c — ELF Binary Parser

Requirements for `elf_open()`, `elf_close()`, `elf_find_avros_tables()`, and `elf_flash_addr()`.

*   <a id="LLR-ELF-01"></a>**LLR-ELF-01** — `elf_open()` shall read the first 16 bytes of the ELF binary and verify: the 4-byte magic sequence (0x7F `'E'` `'L'` `'F'`), `EI_CLASS == ELFCLASS32`, and `e_machine == EM_AVR` (0x0053). Any validation failure shall cause `elf_open()` to log a warning and return -1 without any heap allocation.
    *Trace:* HLR-021 (ELF Binary Parsing).

*   <a id="LLR-ELF-02"></a>**LLR-ELF-02** — `elf_open()` shall locate the `.symtab` section (type `SHT_SYMTAB`) and its associated string table section (index given by `sh_link`), and load both into heap-allocated buffers stored in `ctx->symtab` and `ctx->strtab`. `ctx->sym_count` and `ctx->strtab_size` shall be set accordingly. On any `malloc` failure, `elf_open()` shall free all partial allocations and return -1.
    *Trace:* HLR-021 (ELF Binary Parsing), HLR-040 (Bounded Heap Allocation).

*   <a id="LLR-ELF-03"></a>**LLR-ELF-03** — `elf_find_avros_tables()` shall perform a single O(sym_count) linear scan of `ctx->symtab`, compare each symbol name against the 8 avrOS sentinel names defined in SDD §6.3.3, and populate the corresponding fields of `AvrOsSymbolIndex` for each match. The function shall return 0 (success, even if partial) or -1 only on an internal ELF read error.
    *Trace:* HLR-021 (ELF Binary Parsing).

*   <a id="LLR-ELF-04"></a>**LLR-ELF-04** — `elf_flash_addr()` shall convert an ELF virtual memory address to a physical FLASH word address using the formula: `physical_word_addr = (vma - ctx->flash_base) / 2`. All FLASH-resident avrOS symbol addresses stored in `AvrOsSymbolIndex` shall be computed via this function.
    *Trace:* HLR-022 (Harvard Architecture Address Mapping).

*   <a id="LLR-ELF-05"></a>**LLR-ELF-05** — When `elf_find_avros_tables()` completes the symbol scan and fewer than the expected avrOS symbols were found, it shall return 0 (not -1). Fields of `AvrOsSymbolIndex` for absent symbols shall retain their zero-initialised values, and the function shall log an informational message identifying which symbols were not found.
    *Trace:* HLR-023 (Fail-Safe Degradation on Missing Symbols).

*   <a id="LLR-ELF-06"></a>**LLR-ELF-06** — `elf_close()` shall free `ctx->symtab`, free `ctx->strtab`, and close `ctx->fd`. After returning, `ctx->symtab` and `ctx->strtab` shall be set to NULL and `ctx->fd` to -1. `elf_close()` shall be safe to call on a partially initialised `ElfContext` (e.g., after a failed `elf_open()`).
    *Trace:* HLR-040 (Bounded Heap Allocation).

*   <a id="LLR-ELF-07"></a>**LLR-ELF-07** — `src/elf_parser.c` shall obtain ELF32 type definitions via a platform-conditional include: on Linux (`#ifdef __linux__`) it shall use the system header `<elf.h>`; on all other platforms it shall include the bundled portability shim `src/elf.h`. The shim shall define at minimum: `Elf32_Half`, `Elf32_Word`, `Elf32_Off`, `Elf32_Addr`, `Elf32_Ehdr`, `Elf32_Phdr`, `Elf32_Shdr`, `Elf32_Sym`, the `ELFMAG`/`SELFMAG` magic constants, `EI_CLASS`, `ELFCLASS32`, `EM_AVR` (0x0053), `PT_LOAD`, `SHT_SYMTAB`, `SHT_STRTAB`, `SHN_UNDEF`, and the `ELF32_ST_BIND`/`ELF32_ST_TYPE` accessor macros.
    *Trace:* HLR-033 (Native Linux and macOS Build).

*   <a id="LLR-ELF-08"></a>**LLR-ELF-08** — `elf_open()` shall iterate over all ELF program headers and identify `PT_LOAD` segments. The first `PT_LOAD` segment encountered shall be treated as the FLASH load segment: its `p_vaddr` and `p_filesz` shall be stored in `ctx->flash_base` and `ctx->flash_size` respectively. The second `PT_LOAD` segment shall be treated as the SRAM load segment: its `p_vaddr` and `p_memsz` shall be stored in `ctx->sram_base` and `ctx->sram_size` respectively. If fewer than two `PT_LOAD` segments are present the absent values shall remain zero. These fields are the sole inputs to `elf_flash_addr()`.
    *Trace:* HLR-021 (ELF Binary Parsing), HLR-022 (Harvard Architecture Address Mapping).

*   <a id="LLR-ELF-09"></a>**LLR-ELF-09** — `elf_open()` shall best-effort extract the lowercase Microchip part-name string from the `.note.gnu.avr.deviceinfo` ELF note emitted by avr-gcc + Microchip device packs (binutils ≥ 2.27). The parser shall walk every section of type `SHT_NOTE`, validate the standard ELF note prologue (`namesz = 4`, `type = 1`, `name = "AVR\0"`), then scan the descriptor bytes for the first NUL-terminated ASCII run starting with `"avr"` followed immediately by an ASCII digit. Up to `ELF_DEVICE_NAME_MAX - 1` (15) bytes shall be copied into the new `ElfContext.device_name` field and NUL-terminated. The note-format heuristic — scanning for `"avr<digit>…"` rather than decoding the descriptor's full struct — is intentional, so the parser survives binutils version drift in the descriptor layout. When the note is absent, malformed, or contains no recognised part-name, `device_name` shall remain the empty string the entry path cleared (`ctx->device_name[0] = '\0'`), which `app_main()` (LLR-MAIN-13) treats as "ELF carries no device identification" and which `updi_family_from_partname()` (LLR-UPDI-28) maps to `NULL`. This LLR shall not cause `elf_open()` to fail on any input that already passes the ELF32/EM_AVR validation in LLR-ELF-01.
    *Trace:* HLR-021 (ELF Binary Parsing), HLR-048 (Multi-Family Runtime Device Dispatch).

## 6. src/fsm_mapper.c — FSM State Snapshot Provider

Requirements for `fsm_build_thread_list()`, `fsm_invalidate()`, and `fsm_get_active_thread()`.

*   <a id="LLR-FSM-01"></a>**LLR-FSM-01** — `fsm_build_thread_list()` shall read `idx->fsm_table_count` consecutive 9-byte `fsmStateMachineDescr_t` records from the FLASH address `idx->fsm_table_addr` via `updi_mem_read()`. Each descriptor carries a 2-byte `name` pointer (FLASH), a 2-byte `stateMachine` pointer (SRAM, or NULL for an initializer slot that shall be skipped), a 2-byte `handler` function pointer, a 1-byte `priority`, and a 2-byte `instance`. The FLASH addresses (`fsm_table_addr` and the per-entry `name` pointers) are physical byte LMAs / translated by `idx->flash_lma_off` before the UPDI flash read, because the AVR-Dx mapped-flash window FLMAP is not applied to linear UPDI flash reads. For each non-NULL `stateMachine` pointer, the function shall read the 2-byte `currStateName` pointer at offset 0 of `fsmStateMachine_t` and resolve it (NUL-terminated; a non-printable byte is treated as the terminator) into `thread->state_name`; a NULL pointer (FSM not yet dispatched) yields an empty state name. A UPDI read failure at any point shall cause the function to return -1.
    *Trace:* HLR-024 (FSM Thread Enumeration).

*   <a id="LLR-FSM-03"></a>**LLR-FSM-03** — `fsm_build_thread_list()` shall read the 2-byte SRAM value at `idx->current_fsm_addr` (avrOS `currStateMachine`) and compare it against each retained FSM entry's `stateMachine` pointer. The matching entry shall have `thread->is_active = true` and its identifier stored in `ctx->active_id`. If no entry matches, `ctx->active_id` shall be set to 0.
    *Trace:* HLR-025 (Active Thread Identification).

## 7. src/monitor.c — avrOS System Introspection

Requirements for `monitor_dispatch()` and its static sub-command helpers `cmd_events()` and `cmd_queues()`.

*   <a id="LLR-MON-01"></a>**LLR-MON-01** — `monitor_dispatch()` shall hex-decode the ASCII-hex-encoded `cmd` string (pairs of hex digit characters) into a plain-text command string before any prefix or sub-command matching is attempted. An odd-length or invalid hex-digit sequence shall be treated as an unrecognised command.
    *Trace:* HLR-029 (Monitor Events Command).

*   <a id="LLR-MON-02"></a>**LLR-MON-02** — `monitor_dispatch()` shall verify that the decoded command string begins with the prefix `"avros "` (case-sensitive, including the trailing space). If the prefix does not match, the function shall send a usage-hint O-packet to the GDB console and return -2.
    *Trace:* HLR-029 (Monitor Events Command), HLR-030 (Monitor Queues Command).

*   <a id="LLR-MON-03"></a>**LLR-MON-03** — `cmd_events()` shall call `updi_mem_read()` to read `idx->event_count` consecutive 4-byte `evntDescriptor_t` records from FLASH at `idx->event_table_addr`. For each descriptor it shall dereference the `name` pointer (FLASH) to read the event's NUL-terminated display name (up to 31 chars) and the `status` pointer (SRAM) to read the 1-byte status flag, then append a line of the form `"  <name>: <status>\n"` and send the complete buffer as RSP O-packets.
    *Trace:* HLR-029 (Monitor Events Command).

*   <a id="LLR-MON-04"></a>**LLR-MON-04** — `cmd_queues()` shall call `updi_mem_read()` to read `idx->queue_count` consecutive 10-byte `queDescriptor_t` records from FLASH at `idx->queue_table_addr`. For each descriptor it shall extract and format the `capacity` and `sizeOfElement` fields as a one-line entry and send the complete table as RSP O-packets.
    *Trace:* HLR-030 (Monitor Queues Command).

*   <a id="LLR-MON-06"></a>**LLR-MON-06** — All monitor output shall be assembled into a temporary buffer of at most 512 bytes, hex-encoded (each ASCII byte converted to 2 hex characters per RSP O-packet spec), and transmitted to the GDB client as one or more RSP O-packets via `rsp_send_packet()`.
    *Trace:* HLR-029 (Monitor Events Command), HLR-030 (Monitor Queues Command).

*   <a id="LLR-MON-07"></a>**LLR-MON-07** — `monitor_dispatch()` and all of its static helpers (`cmd_events()`, `cmd_queues()`) shall use `updi_mem_read()` exclusively for all target memory access. None of these functions shall call `updi_halt()`, ensuring that monitor commands never interrupt firmware execution.
    *Trace:* HLR-011 (Non-Intrusive Background Memory Read), HLR-032 (Introspection Reliability).

*   <a id="LLR-MON-08"></a>**LLR-MON-08** — `monitor_dispatch_ex(int rsp_fd, RspContext *ctx, const char *cmd)` shall be the top-level entry for `qRcmd` packets and shall hex-decode `cmd` into a writable buffer of at least 256 bytes, then dispatch on the first whitespace-stripped token. If the token is `avros` followed by a space the call shall be forwarded verbatim to the legacy `monitor_dispatch()` so all pre-existing `monitor avros …` sub-commands keep working unchanged. Recognised top-level verbs are `reset`, `halt`, `go`, `erase`, `chip-erase`, `version`, `bp-mode`, and `help`. Any other first token shall emit an O-packet `"usage: monitor <reset|halt|go|erase|chip-erase|version|bp-mode|help|avros …>\n"` and return -2.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-09"></a>**LLR-MON-09** — The `monitor reset` verb shall call `updi_enter_debug(ctx->updi_fd)` (issuing the OCD KEY + ASI_RESET_REQ pulse and waiting for the STOPPED bit so the CPU is halted at the reset vector), discard all hardware-breakpoint shadow entries via `rsp_hw_bp_clear_all(ctx)`, invalidate the FSM snapshot cache via `fsm_invalidate(ctx->fsm)` when `ctx->fsm` is non-NULL, emit one diagnostic O-packet line `"target reset, halted at reset vector\n"`, and return 0 so `dh_monitor` appends the trailing `OK`.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-16"></a>**LLR-MON-16** — `monitor_dispatch()` shall route the decoded sub-command `tasks` to `cmd_tasks()`, which builds the FSM snapshot via `fsm_build_thread_list()` and emits one O-packet line per FSM (an active marker, the FSM name, and the current state name, or `(init)` when `currStateName` is NULL), returning 0. When no FSMs are registered it emits a single "(no FSMs registered)" line.
    *Trace:* HLR-069 (Monitor Tasks Command).

*   <a id="LLR-MON-10"></a>**LLR-MON-10** — The `monitor halt` verb shall call `updi_halt(ctx->updi_fd)` and then emit the same stop-reply packet shape used by the step/continue paths — `T05thread:<id>;` where `<id>` is `fsm_get_active_thread(ctx->fsm)` (or 1 when no FSM mapping is available) — via `rsp_send_packet()`. The verb shall return -3 so `dh_monitor` suppresses the trailing `OK` and the GDB client sees exactly one packet per halt.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-11"></a>**LLR-MON-11** — The `monitor go` verb shall call `updi_run(ctx->updi_fd)`, emit a diagnostic O-packet `"target running\n"`, and return 0. The subsequent stop-reply is emitted by the existing poll loop when the CPU next halts; the verb itself does not synthesise one.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-12"></a>**LLR-MON-12** — The `monitor erase` verb (alias `monitor chip-erase`) shall consult `ctx->allow_erase` before issuing any UPDI traffic. When the flag is zero, the verb shall emit one diagnostic O-packet `"monitor erase: refused — launch the server with --allow-erase to enable.\n"` and return -1 so `dh_monitor` sends an `E22` error packet. When the flag is set the verb shall call `updi_chip_erase(ctx->updi_fd)`, then re-enter OCD via `updi_enter_debug()`, discard all BP/WP shadow entries, invalidate the FSM snapshot cache, emit a confirmation O-packet, and return 0.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-13"></a>**LLR-MON-13** — The `monitor version` verb shall emit one O-packet of the form `"avrOSdb <version> (built <date>)\n"` where `<version>` is the compile-time string `AVROSDB_VERSION` (supplied by the Makefile via `-DAVROSDB_VERSION='"$(VERSION)"'`) and `<date>` is the standard `__DATE__` macro. It shall return 0.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-14"></a>**LLR-MON-14** — The `monitor bp-mode <arg>` verb shall accept exactly two argument tokens: `sw` (sets `ctx->bp_mode = RSP_BP_MODE_SW`, the default) and `hw-only` (sets `ctx->bp_mode = RSP_BP_MODE_HW_ONLY`). With no argument it shall report the current setting. Any other argument shall emit an error O-packet and return -2. The mode persists for the lifetime of the server process and influences how `Z0` packets are routed (HLR-054).
    *Trace:* HLR-054 (True Software Breakpoints via FLASH BREAK Opcode), HLR-055 (avarice-Compatible Monitor Commands).

*   <a id="LLR-MON-15"></a>**LLR-MON-15** — The `monitor help` verb shall emit one O-packet per recognised verb, each line briefly summarising the verb's syntax and side-effects, in the order: `reset`, `halt`, `go`, `erase`, `chip-erase`, `version`, `bp-mode`, `help`, `avros events`, `avros queues`. After the last line it shall return 0 so `dh_monitor` terminates the output with `OK`.
    *Trace:* HLR-055 (avarice-Compatible Monitor Commands).

Requirements for the manual-only on-target hardware integration test program. The harness links against `src/updi.c` (and, for Group D, spawns the production `build/avrOSdb` binary via `fork`/`execl`) and runs against live AVR-Dx silicon connected via a UART/UPDI adapter.

*   <a id="LLR-HWTEST-01"></a>**LLR-HWTEST-01** — `tests/hw/hw_test.c` shall accept its configuration from environment variables and from long-form command-line options. Recognised settings: `HW_PORT` / `--port` (serial device path; default `/dev/ttyUSB0`), `HW_DEVICE_ID` / `--device-id` (expected 24-bit SIGROW signature as a hex literal; default `0x1E970A` for AVR128DA48), `HW_SRAM_ADDR` / `--sram-addr` (16-bit SRAM probe address; default `0x7000`), `HW_FLASH_PAGE_ADDR` / `--flash-page` (FLASH page-aligned address used by Group C; default `0x1FE00`), `HW_RSP_PORT` / `--rsp-port` (TCP port for Group D; default `1234`), `HW_TEST_ELF` / `--elf` (optional ELF binary passed to the spawned RSP server in Group D), `HW_ADDR_24BIT` / `--addr-24bit` (boolean; when true, FLASH access uses the 24-bit UPDI addressing path), and `HW_VERBOSE` / `--verbose` (boolean; enables per-byte tracing). CLI flags shall override the corresponding environment values.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness).

*   <a id="LLR-HWTEST-02"></a>**LLR-HWTEST-02** — Group A (read-only link probes) shall execute the following ordered checks against the live target: **A1** open the serial port and perform the UPDI cold-start handshake (BREAK + SYNCH); **A2** call `updi_read_device_info()` and capture the result for downstream assertions; **A3** verify that the captured `DEVICEID0..2` bytes match the configured `HW_DEVICE_ID`; **A4** verify that the SIGROW signature is not all-zero and not all-`0xFF`; **A5** verify that `SYSCFG.REVID` is non-zero; **A6** verify that the 10-byte `SERNUM` field is not all-zero and not all-`0xFF`; **A7** verify that `ASI_SYS_STATUS.NVMPROG` is clear (target is not stuck in a programming session). Each individual check shall be reported as a separate `[PASS]`/`[FAIL]` line.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness), HLR-044 (Device-Signature Diagnostic Mode).

*   <a id="LLR-HWTEST-03"></a>**LLR-HWTEST-03** — Group B (non-destructive SRAM round-trips) shall execute the following ordered checks at `HW_SRAM_ADDR`: **B0** single-byte write/read; **B1** 64-byte buffer write/read; **B1a** SIGROW read repeated twice and compared (isolates the read path from the write path); **B1b** write 64 bytes of constant `0xAA` then read back (value-independence check); **B1c** write a known pattern once then read it back twice and compare both reads (detects live CPU writes to the probed region — on failure the harness shall hint that the operator pick a different `--sram-addr` / `HW_SRAM_ADDR`); **B2** 600-byte buffer write/read (exercises multi-chunk transfer); **B3** when `HW_ADDR_24BIT` is true, a small write/read at the configured FLASH page address using the 24-bit UPDI addressing path. None of the Group B steps shall modify FLASH.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness), HLR-011 (Non-Intrusive Background Memory Read).

*   <a id="LLR-HWTEST-04"></a>**LLR-HWTEST-04** — Group C (destructive FLASH write/verify) shall execute only when the environment variable `HW_TEST_NVM_CONFIRM=YES` is set; otherwise the group shall be reported as skipped. When confirmed, Group C shall perform: **C1** erase the FLASH page at `HW_FLASH_PAGE_ADDR`, then write a deterministic pattern via the NVM controller; **C2** read the page back and verify a byte-for-byte match against the written pattern. The harness shall enter and leave the NVM programming session cleanly (NVMPROG key in, NVMPROG key cleared on exit) so that subsequent Group A/B checks find the target in a non-programming state.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness), HLR-008 (Flash Write).

*   <a id="LLR-HWTEST-05"></a>**LLR-HWTEST-05** — Group D (RSP server spawn-and-probe) shall execute only when the environment variable `HW_TEST_RSP=YES` is set; otherwise the group shall be reported as skipped. When enabled, Group D shall `fork` and `execl` the production `build/avrOSdb` binary with the configured serial port and optional `HW_TEST_ELF`, wait briefly for the server's TCP listener to bind on `HW_RSP_PORT`, then perform: **D1** connect a TCP client to `127.0.0.1:HW_RSP_PORT` and verify the connection is accepted; **D2** send an RSP `qSupported` packet (`$qSupported#37`) and verify a non-empty, properly-framed RSP reply is received. The harness shall terminate the spawned server cleanly (SIGTERM + `waitpid`) on completion or on test failure.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness), HLR-014 (GDB RSP TCP Listener).

*   <a id="LLR-HWTEST-06"></a>**LLR-HWTEST-06** — The Makefile shall expose four targets that drive `tests/hw/hw_test.c`: `hw-test` runs Groups A+B (read-only); `hw-test-nvm` runs Groups A+B+C and forwards `HW_TEST_NVM_CONFIRM=YES`; `hw-test-rsp` runs Groups A+B+D and forwards `HW_TEST_RSP=YES`; `hw-test-all` runs all four groups. Every hw-test variable (`HW_PORT`, `HW_DEVICE_ID`, `HW_SRAM_ADDR`, `HW_FLASH_PAGE_ADDR`, `HW_RSP_PORT`, `HW_TEST_ELF`, `HW_ADDR_24BIT`, `HW_VERBOSE`) shall be passed through to the child process via the target recipes. None of these targets shall be a dependency of the default `make test` target or be built by `make all`. The `make help` output shall document each variable, its default, and a brief description.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness).

*   <a id="LLR-HWTEST-07"></a>**LLR-HWTEST-07** — Group F (Phase 9 link diagnostics) shall execute three on-target checks: **F1** call `updi_probe_baud(cfg->port, 8, visitor, NULL)`, record each rung's `{baud, errors, samples}`, and PASS if the chosen rate is ≥ 19200 baud (the slowest rung in the ladder); **F2** with the harness UPDI fd re-opened at the configured baud, read the FUSES window and the 4-byte LOCK window via `updi_nvm_read()`, format them via `updi_format_fuses()` into a 2 KiB buffer, and PASS if the output contains the literal substrings `WDTCFG`, `OSCCFG`, `SYSCFG0`, and `Lock:`; **F3** (destructive, gated by `HW_TEST_NVM_CONFIRM=YES`) fork the production `build/avrOSdb --prog --erase --baud <N> <port> <elf>` against the bench ELF, capture the child's stdout/stderr, and PASS if `WEXITSTATUS == 0` AND the captured output contains the literal `verify: OK`. F1 needs the harness UPDI fd closed before running (so the probe can open its own fd at each rung); the harness shall close fd before F1, re-open at `cfg->baud` for F2, then close again before F3.
    *Trace:* HLR-045 (On-Target Hardware Integration Test Harness), HLR-049 (Read-Back Verify After Load), HLR-050 (Program-and-Exit Mode), HLR-051 (Fuses Pretty-Printer in Device Mode), HLR-052 (Auto-Baud Link-Quality Probe in Device Mode).

*   <a id="LLR-HWTEST-08"></a>**LLR-HWTEST-08** — Group D's RSP-server smoke checks shall, after the existing D1–D3 (TCP accept, qSupported, Ctrl-C interrupt) pass, additionally exercise the Phase-10 RSP surface against the same spawned `build/avrOSdb` child over the same TCP socket: **D4** issue a framed `qC` packet and PASS if the reply payload begins with `QC` followed by a thread id; **D5** issue `qOffsets` and PASS if the reply payload begins with `Text=`; **D6** issue `qRcmd,696e666f` (the hex-encoded `monitor info` verb) and PASS if the reply payload is non-empty and does not begin with `E` (an error code); **D7** issue `Z2,<sram_addr|0x800000>,1` then `z2,<sram_addr|0x800000>,1` and PASS only if both replies are the empty packet (`$#00`, payload length zero) — the silicon has no data-watchpoint hardware (HLR-056); **D8** issue `vRun;` and PASS if the reply payload begins with `T` (any stop signal); **D9** (destructive, opt-in via `--with-nvm`) issue `vFlashErase:<flash_page>,200` followed by `vFlashDone` and PASS if both replies are `OK`; **D10** (destructive, opt-in via `--with-nvm`, must be ordered after D9 so the page baseline is 0xFF) issue `Z0,<flash_page>,2`, then read back with `m<flash_page>,2` expecting the 4-character hex literal `9895` (AVR `BREAK` opcode little-endian), then issue `z0,<flash_page>,2`, and PASS only when all three exchanges produce the expected replies. When `--with-rsp` is not set, D4–D10 shall be skipped together with D1–D3; when `--with-nvm` is not set, only D9–D10 shall be reported as SKIP. A short helper `send_rsp(fd, payload)` shall compute the modulo-256 RSP checksum and ship `+$<payload>#XX`; a companion `rsp_payload(buf, n, &p, &len)` shall locate the `$…#` payload in a raw reply buffer.
    *Trace:* HLR-053 (Flash Programming via GDB load), HLR-054 (True Software Breakpoints via Flash BREAK Opcode), HLR-055 (avarice Monitor Verb Parity), HLR-056 (Data Access Watchpoints), HLR-058 (vRun / vAttach / vKill), HLR-059 (qC / qOffsets / T / R Replies).
